## 4. 분석 (해석)

### 4.1 H1: 같은 보정에서 고정 타임아웃보다 낫다
- 주 AI는 같은 그림자 장부·보정 주기·대체 장치를 쓰는 고정 타임아웃보다 독립 실제 창에서 비용이 낮았다. Azure(14/0/0)와 BurstGPT(23/12/4) 모두 같은 방향이었고, 개발 데이터로 한 번 학습한 pre 판(36/17/1)도 같았다.
- 대체 장치가 안전성을 만들었다. 대체 없는 주 AI는 승이 39개로 비슷했지만 패가 11개였고 최악 창이 +117.7%p(T* = 1초)였다. 대체를 넣으면 패가 4개, 최악이 +2.34%p로 줄었다.

### 4.2 H2: 2특징 규칙이 T* = 1초에서 더 강했다
- 같은 온라인 보정을 쓴 2특징 규칙은 고정-온라인 대비 d 중앙 −9.70%p로, 주 AI(−7.68%p)보다 더 줄였다. H1의 이득은 'AI만의 이득'이 아니다. 같은 보정 장치를 쓰는 단순 규칙이 이 조건에서 더 많이 줄였다.
- 순서는 T*에 따라 뒤집혔다(탐색). T* = 0.3초는 비겼고, 1초는 규칙이, 3·10초는 AI가 나았다. 개발 데이터에서는 반대로 1초에서 AI가, 3초에서 규칙이 나았다.
- 판정 조건 T* = 1초는 개발 데이터에서 AI가 가장 유리해 보인 조건이었다(사전 등록 §8에 미리 밝힌 한계). 봉인 데이터에서 그 우위는 재현되지 않았다. AI와 규칙의 순서는 T*와 데이터에 따라 바뀌었고, 한 데이터에서 본 우열이 다른 데이터로 옮겨 가지 않았다(추론).
- Azure 창에서 규칙 우세가 뚜렷했다(1/1/12). 솎기 민감도 6창에서는 8건/s의 차이(+2.4~+3.7%p)가 16건/s에서 6창 모두 줄었다. 따라서 Azure에서의 규칙 우세는 8건/s 솎기와 서버 규모에 일부 기대고 있을 수 있다. 다만 6창의 탐색이라 판정을 바꾸지 않는다.

### 4.3 차이가 생기는 곳: 특징 수가 아니라 모델링·보정 방식
- 특징을 1~2개에서 15개로 늘려도(15/26/12), 입력 패턴 특징 5개를 빼도(9/36/8) 주 AI의 비용은 거의 그대로였다. 연구 동기였던 '입력 패턴 특징'의 몫은 검출되지 않았다.
- 같은 1~2개 특징을 쓴 2특징 AI도 규칙보다 나빴다(7/11/35). 그래서 T* = 1초의 차이는 정보가 아니라 쓰는 방식에서 생긴다. 즉 '조각별 생존 곡선 × κ 하나'와 '칸별 반납 시점을 장부로 직접 맞추기'의 차이다(추론).
- 칸별 보정을 쓰는 AI생존그룹도 규칙보다 나빴다(12/14/27). 규칙의 칸(높이×수준이 가장 많았다)이 이 비용 구조에 잘 맞는 묶음일 가능성이 있다(추정).
- 비용 분해에서 주 AI는 보유 메모리를 더 줄였지만(−14.6% vs −11.3%) 재확보는 줄이지 못했다(+0.0% vs −1.4%). 대체 장치가 고정-온라인으로 돌아간 비율도 AI가 더 컸다(평균 0.27 vs 0.16). AI는 보유를 줄이는 쪽으로 반납했고, 그 대가로 재확보를 줄이지 못해 T* = 1초의 비용에서 규칙에 밀렸다고 읽힌다(추론).

### 4.4 불규칙성: 'AI가 불규칙할수록 유리하다'는 지지되지 않았다
- 실제 창의 네 칸 모두에서 AI와 규칙의 차이를 검출하지 못했다(H3).
- 조작한 합성 실험에서는 짧은 몰림이 있으면 AI의 규칙 대비 이득이 오히려 작아졌다(H4). 크기 변동의 효과는 개발 데이터와 같은 방향(크기 변동이 크면 이득이 작다)이었지만 검출되지 않았다.
- 실제 창의 상관은 약했다(|ρ| ≤ 0.25). burst의 부호(−0.25, 몰림이 클수록 AI 쪽이 상대적으로 낫다)는 H4와 반대였다. 실제 창의 지표는 시간대·모델 구성과 함께 움직이므로 원인 주장은 H4로만 한다(사전 등록 §8).

### 4.5 논문에 쓸 수 있는 주장
- 쓸 수 있다: H1 문장. "같은 조건에서 2특징 규칙보다는 비용이 높았다." T*별 결과(탐색으로 표시). 합성 실험의 짧은 몰림 효과.
- 쓸 수 없다: "AI가 규칙보다 낫다", "불규칙한 부하에서 AI가 유리하다", "모든 T*에서 낫다", "입력 패턴 특징이 비용을 줄인다", "실제 할당기·메모리 제한에서 낫다"(3단계 전).
- AI 중심의 주장은 'AI 생존 정책이 jemalloc 감쇠에 해당하는 고정 타임아웃을 같은 보정 조건에서 이긴다'까지다. 규칙과의 비교는 부정 결과로 함께 보고해야 한다.

## 6. 사후 분석 (판정 뒤에 정했다, 판정을 바꾸지 않는다)
- 외부 검토의 지적 두 가지(H1 단위 독립성, H4 시드 반복)를 확인하려고 판정 뒤에 정한 분석이다. 코드와 출력은 `exp/sealed/res/posthoc/`에 있다.

### 6.1 H1·H2의 단위: Azure 같은 날짜 합침
- R 집합의 Azure 14창은 code 7일(2024-05-10~16)과 conv 7일(2024-05-12~18)에서 하나씩 뽑았다. 달력 날짜는 9일이고, 그중 5일에 창이 2개(code·conv) 있다. BurstGPT 39창은 서로 다른 (파일, 날) 군집이고, BurstGPT_2와 _3은 서로 다른 기간이다(BurstGPT README).
- 같은 날짜의 Azure 창 두 개를 d의 평균으로 합쳐 48단위로 다시 계산했다(T* = 1초).

| 비교 | 등록 분석 (53단위) | 합친 분석 (48단위) |
|---|---|---|
| H1 주 AI vs 고정-온라인 | 37/12/4, p = 1.0×10⁻⁷, d 중앙 −7.68, 후퇴 7.5% | 32/12/4, p = 1.9×10⁻⁶, d 중앙 −7.31, 후퇴 8.3% |
| H2 주 AI vs 규칙-온라인+대체 | 9/14/30, p = 0.0011, d 중앙 +1.16 | 8/14/26, p = 0.0029, d 중앙 +1.13 |

### 6.2 H4: 시드 블록
- 합성 40개는 시드 5개 × 조건 8개다. 등록 분석(Mann–Whitney)은 40개를 서로 독립으로 다뤘다. 같은 시드 안에서 다른 두 요인 수준이 같은 두 트레이스를 짝지어(요인마다 20쌍) 다시 계산했다.
- 시드별 d 평균은 −2.38~−3.83%p였다.

| 요인 | 짝 차이 중앙(%p), 양수 개수 | Wilcoxon p (Holm 3) | 시드별 평균 5개 | t-검정 p (Holm 3) |
|---|---|---|---|---|
| 크기 변동 | +1.08, 13/20 | 0.105 (0.105) | 0.61, 1.59, 2.54, −0.37, 1.43 | 0.077 (0.077) |
| 짧은 몰림 | +1.70, 15/20 | 0.0064 (0.019) | 2.04, 0.37, 2.99, 3.27, 2.01 | 0.014 (0.027) |
| 수준 변화 | −1.63, 6/20 | 0.027 (0.053) | −1.02, −2.42, −2.08, −1.93, −1.30 | 0.0025 (0.0074) |

- 짧은 몰림의 효과는 두 블록 분석에서 모두 Holm p < 0.05였고 방향(몰림이 있으면 AI의 규칙 대비 이득이 작다)은 시드 5개 모두 같았다.
- 수준 변화는 등록 분석에서 검출하지 못했고(Holm p = 0.067), 블록 분석에서는 방법에 따라 갈렸다(Wilcoxon Holm 0.053, t-검정 Holm 0.0074). 방향(파도가 있으면 AI의 이득이 크다)은 시드 5개 모두 같았다. 사후 분석이므로 확정으로 쓰지 않는다.

### 6.3 실행 점검
- `res_main.csv`·`res_fx.csv`·`res_sens.csv`의 (proto, trace, T*, policy) 중복 행은 0개였다. 실제 실행은 묶음마다 새 임시 파일에 쓰고 종료 코드를 확인한 뒤 옮겼다(`run_sealed_parts.sh`). 묶음 23개가 모두 끝났고 실패는 0개였다.
- 등록 스크립트 `run_sealed.sh`는 출력 CSV에 덧붙이고 백그라운드 작업의 종료 코드를 따로 확인하지 않는다. 이번 실행에는 쓰지 않았지만, 다음 사전 등록의 실행 스크립트는 분할 실행판의 방식(새 파일, 종료 코드 확인)으로 고정한다.

### 6.4 해석 (사후)
- H1·H2의 결론은 단위를 날짜로 합쳐도 같았다.
- H4의 짧은 몰림 효과는 시드 블록을 고려해도 유지됐다. 다만 합성 실험의 결과이고, 실제 창의 상관(burst ρ = −0.25)과 방향이 다르므로 실제 부하로 일반화하지 않는다.
