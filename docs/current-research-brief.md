# 현행 연구 지침 (2026-11-04)

> 이 문서는 지금 연구의 질문, 결과의 보고 순서, 쓰는 표현과 쓰지 않는 표현을 정한다.
> 논문을 쓰거나 AI 코딩 도구로 작업할 때는 이 문서를 먼저 따른다. 다른 문서와 다르면 이 문서를 따르고, 다른 점을 알린다.
> 사전 등록 문서와 과거 결과 문서는 고치지 않고 당시 기록으로 보존한다(§6).

## 1. 연구 질문과 대상

- **핵심 질문**: 예측 기반 메모리 반납 정책이 자신의 학습·추론 CPU 비용까지 회수할 수 있는가?
- **대상**
  - 요청 본문을 담는 1 MiB 청크 풀에서, 놀고 있는 청크를 언제 운영체제에 돌려줄지 정한다.
  - 결정 변수는 반납 시점 하나다. 미리 확보해 두는 것은 재확보 횟수를 줄이지 못하므로 다루지 않는다.
- **비용 모델**
  - 비용 = 재확보 MiB + 낭비 MiB·초 ÷ T*다.
  - 판정 T* = 2.6초다. 연구자 WSL에서 잰 재확보 비용(1 MiB 청크, 4 KiB 페이지)에 AWS Fargate 가격 비율을 곱해 정했다. 가격 비율은 모델링 가정이다.
  - 비용 단위 1은 CPU 281.8 µs(c)에 해당한다.
- **정책**(정의는 `docs/prereg-v2.md` §3)
  - 고정-온라인: 반납 시점 하나를 그림자 장부로 온라인 보정한다.
  - 2특징 규칙: 특징 2개로 나눈 칸마다 반납 시점을 온라인 보정하고, 대체 장치를 붙였다(규칙-온라인+대체).
  - v1 주 AI: 생존 모델(HistGradientBoosting, 매듭 10개)이 조각별 반납 시점을 내고 κ를 온라인 보정하며, 대체 장치를 붙였다(AI생존κ-온라인+대체).
  - C3: 최근 300초 그림자 장부 비용이 낮은 쪽으로 v1 주 AI와 2특징 규칙 사이를 전환한다(AI→규칙대체).
  - 오라클: 조각의 놀이 시간을 아는 비용 하한이다. 구현할 수 없다.
- **평가 모델**: 청크 풀 유체 모델 시뮬레이션이다. 3단계 재생에서 재확보량은 실제 청크 풀과 같았다. 단편화, 백그라운드 회수, 메모리 제한은 모델에 없다.

### c의 실측 정의와 T*의 가격 환산

- `c = 281.8 µs/MiB`는 3단계에서 측정한 CPU 시간이다. 1 MiB 청크, 4 KiB 페이지, `MADV_DONTNEED`, 묶음 16 조건에서 반납 25.6 µs/MiB와 재확보 256.2 µs/MiB의 합이다.
- 가격 비율은 `c`에 들어가지 않는다. CPU 1초 = `9.107 × 1,024 MiB·s`로 환산하면 `1 MiB·s = 107.2 µs`이고, `c / 107.2 µs ≈ 2.63 s`다. 이는 3단계 측정 범위 2.61~2.64초와 일치한다. 기존 v2에서 동결한 `T* = 2.6 s`는 후속 실험에서 바꾸지 않는다.
- 주 판정은 `G_model = c × (ΔR + ΔH/T*) − ΔI`다. `G_CPU = c × ΔR − ΔI`는 비용 분해로만 보고하고 판정·중단 기준으로 사용하지 않는다. 메모리 제한이 없는 유체 모델에서는 CPU-only 값만으로 정책을 판정할 경우 반납하지 않는 정책이 CPU 사용량이 작다는 이유로 유리해질 수 있다.

## 5. 현재 범위와 2026-11-04 신규 후속 가설

### 5.1 기존 결과의 동결

- 기존 v1/v2 사전 등록, 봉인 결과, 작업 A·B 결과는 당시 기록으로 보존한다. 기존 결과 파일과 사전 등록 문서를 소급 수정하지 않는다.
- v2 봉인 41일 자료는 새 정책의 개발·튜닝 자료로 사용하지 않는다.
- G1은 이미 C3 선택·A·B에 사용한 개발 40일·420개 창의 탐색적 선별이다. 확증 자료가 아니다.

### 5.2 신규 후보: 저차원 생존 GBDT → 무손실 조회표

- 이전 15특징 교사 모델 → 학생 증류 → 수동 캐시/양자화 경로는 채택하지 않는다. 교사 추론 라벨링 비용과 근사 오차를 추가하기 때문이다.
- 실제 생존 라벨 `1[g > τk]`로 2특징 또는 3특징 생존 GBDT 10개를 직접 학습한다. 교사 출력을 학생 라벨로 만들지 않는다.
- 특징은 고정한 26개 개발 일정의 검증 구간에서 기존 `rule_groups`가 선택한 특징 빈도를 집계한다. 빈도 순위와 동률 규칙은 G1 전에 커밋한다.
- P1은 2특징, `max_bins=255`, 최대 256개 상태(비결측 코드 255 + 결측 1)의 `256²` 바이트 표(64 KiB)를 사용한다.
- P1b는 3특징, `max_bins=64`, 최대 65개 상태(비결측 코드 64 + 결측 1)의 `65³` 바이트 표(274,625 byte, 약 268.2 KiB)를 사용한다.
- 두 후보는 26개 `TR` 학습 구간에서 특징별 공통 분위 격자를 한 번 만들고, 원시 특징을 정수 코드로 변환해 10개 매듭 모델에 동일하게 입력한다. cutpoint·중복 처리·경계 비교·NaN/비유한 값 처리 규칙을 고정한다.
- 조회표는 가능한 모든 공통 코드 조합을 10개 실제 모델에 통과시켜 만든 최종 반환 시간 인덱스를 저장한다. 저차원 코드화 모델의 출력과 동등하며 기존 15특징 모델과 동등하다는 뜻은 아니다.
- κ 보정·대체·C3 전환 규칙은 기존 그대로 둔다. 바꾸는 것은 생존 예측기와 그 조회 실행 방식뿐이다.

### 5.3 G1 개발 시뮬레이션 (11/05)

- 26개 고정 일정에서 특징과 공통 분위 격자를 정하고, P1/P1b 모델 및 표를 만든다. 표 출력과 모델 출력이 모든 420개 개발 창의 모든 결정에서 인덱스 단위로 일치해야 한다. NaN·cutpoint 경계 시험도 수행한다.
- 예측기만 바꾼 C3를 420개 창에서 평가하고, 재확보량 감소 `ΔR`과 유휴 보유량 감소 `ΔH`를 분리해 보고한다.
- 탐색 선별 기준은 합성 비용 모델 CPU 등가 `S_model·c ≥ 1.0 s`다(약 0.5 µs/결정, 0.43%p 상당). `G_CPU`와 `c·ΔR`은 비용 분해로 기록하되 G1 통과·중단 기준으로 사용하지 않는다. 실제 순이득은 G2에서 `ΔI`를 측정한 뒤 `G_model`로 판단한다.
- 후보가 모두 통과하면 `S_model·c`가 큰 후보 하나만 G2로 보낸다. 둘 다 실패하면 새 실험을 중단하고 현 원고를 제출한다.

### 5.4 G2 네이티브 CPU 계측 (11/06–07)

- 기존 `c` 측정과 같은 WSL·CPU 1 고정·단일 스레드에서 C++ 하네스로 규칙 경로와 C3 경로를 비교한다. 입력은 사전에 메모리에 적재하고, 두 경로를 교대로 3회 실행하며 실행 순서 효과를 줄인다.
- 두 경로는 같은 사건 흐름과 공통 사건 처리(`D(t)` 갱신, 조각 성숙)를 사용한다. 규칙 경로는 규칙 특징·칸 조회·칸별 장부·고정-온라인 장부·대체 판단을 포함한다. C3는 동일한 규칙 코드를 호출하고, 모든 조각의 표 조회·κ 9개 평가·AI 대체·C3 전환 장부/판단·추가 특징 계산을 더한다.
- C3의 규칙 모드 조각에서도 그림자 장부를 위한 AI 반사실 결정이 필요하므로 모든 조각의 표 조회 비용을 포함한다. 고정-온라인 장부가 두 대체 장치에서 공유되는지 여부는 구현에서 정해 기록한다.
- 증분 장부는 두 경로에 동일한 정수/고정소수점 규칙으로 적용한다. 모든 시험 조각의 규칙 결정·C3 결정·κ·전환 상태가 Python 기준과 일치해야 한다.
- `ΔI = CPU_C3 − CPU_rule`, `G_model = c(ΔR+ΔH/T*)−ΔI`를 주 판정으로 보고, `G_CPU = cΔR−ΔI`는 분해로만 보고한다. 3회 모두 `G_model > 0`이어야 G2를 통과한다. `CPU_rule` 총량과 원시 최소~최대도 함께 기록한다.
- 데이터 준비 `F_data`, 특징 선택 `F_select`, 학습 `F_fit`, 표 생성·검증 `F_table`을 포함해 `F`와 `H* = F·Στ/G_op`를 계산한다. `G_op`은 주 판정인 `G_model`의 누적 운영 순이득이다. 운영 순이득과 생애주기 순이득을 구분하며 `H_deploy`가 정해지지 않으면 `H*`만 보고한다.
- G2가 실패하면 후속 최적화를 더하지 않고 현재 원고를 제출한다.

### 5.5 Copilot 독립 확증 (11/08–09)

- G1·G2 모두 통과한 경우에만 prereg-v3와 코드·표 지문·판정 기준을 커밋한 뒤 원시 Copilot 자료를 연다.
- 26개 개발 일정에서 학습한 표를 재학습 없이 사용하고, v2와 동일한 변환 규칙을 적용해 한 번 평가한다.
- 주 판정은 `G_model > 0`이며, `G_CPU`는 비용 분해 지표로 함께 제시한다. 데이터 확인 이후 정책·특징·판정 기준을 바꾸지 않는다.
- 일정 내 실행되지 않으면 G1/G2 결과는 탐색 결과로만 보고한다.

### 5.6 변경 사유

기존 §5의 “C++ 추론을 측정하지 않는다”, “조회표 경량 예측기를 만들지 않는다”는 제한은 2026-11-04에 수립한 신규 가설 G1/G2를 위해서만 예외적으로 개정한다. 기존 v1/v2 결과의 재실행·변경을 허용하는 것은 아니다. 새 가설은 G1·G2의 사전 고정 중단 기준을 따르며, G1/G2 실패 시 현 논문 원고로 복귀한다.
