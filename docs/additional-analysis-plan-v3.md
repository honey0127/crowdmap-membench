# 추가 분석 계획 v3: 정책 CPU 비용, 위약 대조, 독립 트레이스 검증

**상태:** 실행 전 계획. 이 문서를 커밋한 뒤 A를 실행한다. A 결과로 B의 대상 정책을 선택한다.

**목적:** 기존 v1/v2 봉인 결과를 다시 확증한 것처럼 취급하지 않고, (1) within C3와 사전 학습 C3의 순비용을 평가하고, (2) AI 예측 정보의 기여를 위약 대조로 분해하며, (3) 가능한 경우 독립 Copilot 트레이스 평가를 사전등록한다.

## 1. 비용 정의 및 단위

메모리 가격 비율은 **상대 비용 가중치이자 모델링 가정**이다. 실제 클라우드 청구액 감소나 최대 RSS 감소를 의미하지 않는다. 청크 풀 안의 유휴 청크를 반납해도 작업에 요청한 메모리 용량이 자동으로 줄어들지는 않는다. 실제 자원 절감 주장을 하려면 반납된 메모리를 동일 시간에 사용할 수 있는 다른 소비자와 그에 따른 효과를 별도로 입증해야 한다.

- `c = 281.8 µs/비용 단위`: stage3에서 연구자 WSL, CPU 1 affinity로 측정한 기존 재확보 비용 환산값이다. 이 추가 분석에서는 다시 측정하지 않는다. 모든 새 CPU 측정은 가능한 한 같은 WSL 환경, 같은 CPU affinity, 동일 스레드 설정에서 한다.
- `S`: 동일 평가 구간에서 규칙 기반 정책 비용에서 AI 정책 비용을 뺀 시뮬레이션 이득(비용 단위). 양수면 AI 정책의 시뮬레이션 비용이 낮다.
- `I`: 규칙 기반 정책 경로보다 추가로 필요한 AI 경로 CPU 시간. 실제 온라인 경로에서 추론, 온라인 `κ` 보정, 장부 및 전환 관련 추가 계산을 포함한다. 각 조각의 반사실 AI 결정 `A_i`를 계산하므로 규칙 경로가 실제 선택된 결정도 예측 비용에서 빠지지 않는다.
- `F_within`: within C3의 창별 10개 매듭 모델 `fit` CPU 시간.
- `F_pre`: v1 pre와 동일하게 사전 고정한 학습원으로 사전 학습 C3를 만드는 일회성 CPU 시간.
- `τ`: 평가 시험 구간의 길이.
- `R`: 모델 재학습 주기.

within 판정의 주 계산은 창별 기준으로 한다: `S_w·c`, `I_w`, `F_within`을 모두 창당 값으로 맞춘 뒤 `G_within,w(R)=S_w·c−I_w−F_within·τ/R`를 계산한다. 전체 40일 합계는 별도로 합산해 교차 확인한다. 사전 학습판은 `S_pre,total·c`, `I_pre,total`, `F_pre`를 모두 전체 평가 범위 합계로 맞춘다. 창별 값과 전체 합계를 직접 비교하지 않는다.

## 2. Within C3 비용식 및 판정

시험 구간에 배분되는 순이득은 다음과 같이 정의한다.

`G_within(R) = S·c − I − F_within·τ/R`

`S·c`는 시험 구간의 시뮬레이션 이득을 CPU 시간 등가로 바꾼 값이다. 순이득이 양수인 조건은 `G_within(R) > 0`이다. `S·c ≤ I`이면 학습 비용을 제외해도 순이득이 없다. `S·c > I`일 때 손익분기 재학습 주기는 다음과 같다.

`R* = F_within·τ / (S·c − I)`

`R = R*`에서는 순이득이 0이므로 양의 순이득으로 판정하지 않는다. 측정으로 뒷받침되는 모델 나이 범위는 `R ∈ [τ, 2τ]`로 둔다. 단, 모델 나이 `0~τ`는 측정하지 않았으므로 그 구간의 이득이 모델 나이 `τ~2τ`의 이득보다 작지 않다고 가정한다. 따라서 `[τ, 2τ]` 판정은 이 가정 아래에서만 성립하며, 더 오래 재사용할 경우의 이득은 현재 측정으로 보장하지 않는다.

`F_within`과 `I`는 같은 WSL 환경·CPU affinity·스레드 설정에서 CPU 시간으로 3회 반복 측정한다. 3회 최소–최대 범위는 **경험적 반복 범위**이며 통계적 신뢰구간이라고 부르지 않는다. `R*`의 범위가 `τ` 또는 `2τ` 경계와 겹치면 `판정 불가`로 보고한다. 등호는 손익분기이므로 순이득으로 판정하지 않는다.

### 2.1 A에서 within C3를 판정하는 순서

1. **학습비용만으로 하는 첫 번째 탈락 판정:** `I = 0`으로 두고 `F_within` 3회 중 최솟값으로 `R*`의 낙관적 하한을 계산한다. 이 하한이 `2τ` 이상이면 within은 측정 범위에서 탈락한다.
2. **추론 하한으로 하는 두 번째 탈락 판정:** 실제 매듭 모델 10개로 시험 구간 결정 `N_w`개를 한 번에 예측하는 시간을 단일 스레드로 3회 측정한다. 이 `I_opt`는 오프라인 일괄 예측의 낙관적 실측값이고, 보정·장부 비용은 0으로 둔다. `S·c ≤ I_opt`이면 within은 탈락한다. 시뮬레이터에서 잰 `I`는 오프라인 일괄 값이므로 참고용이며 온라인 비용의 상한·하한으로 취급하지 않는다.
3. **C++ 온라인 측정:** 앞의 두 탈락 판정을 모두 통과한 정책만 C++ 온라인 경로에서 `I`를 3회 측정한다. 실제 온라인 `I`에는 추론, 보정, 장부·전환 관련 추가 계산을 포함한다. CPU 시간 측정은 `c`가 측정된 것과 같은 WSL·CPU affinity·스레드 설정에서 수행한다.
4. 1·2번으로 탈락은 확정할 수 있지만, 생존 판정은 3번의 온라인 경로 측정을 거친 경우에만 내린다.

현재 개발 40일 시뮬레이션에서 within의 이득은 전체 합계 약 `5.78 s`, 창당 평균 약 `13.8 ms`로 기록되어 있다. 첫 번째 탈락 판정은 창당 평균 이득과 창당 fit 평균을 비교한다. `R=2τ`, `I=0`인 조건에서 필요한 평균 `F_within`은 창당 약 `27.5 ms` 미만이다. 두 번째 탈락 판정에서는 모든 평가 창의 `I_opt,w`를 합산해 전체 `S_total·c`와 비교하거나, 양쪽 모두 창당 평균으로 정규화해 비교한다.

## 3. 사전 학습 C3 비용 및 판정

사전 학습원은 **v1 pre와 동일하게** 실행 전에 고정한다. 개발 40일의 모든 창을 `T*=2.6 s`에서 집계하고, `c`는 기존 stage3 값 `281.8 µs/비용 단위`를 그대로 사용한다.

- `S_pre,total·c − I_pre,total`: 운영 중 증분 순이득. 여기서 `I_pre,total`은 모든 평가 창에서의 추론·보정·장부 추가 CPU 비용 합계다.
- `S_pre,total·c − I_pre,total − F_pre`: 일회성 사전 학습비용까지 포함한 생애주기 순이득. `F_pre`는 CPU 시간 단위로 합산한다.

두 기준을 모두 보고한다. 운영 중 증분 순이득이 양수여도 일회성 학습비용을 포함한 생애주기 순이득이 음수라면, 전체 비용상 순이득이라고 주장하지 않는다. 학습 비용을 매몰비용으로 제외한 경우에는 결론을 ‘운영 중 증분 비용’으로 한정한다. 평가한 시험 구간의 합을 `T_eval = 창 수 × τ`로 두고, 필요한 모델 사용시간을 `H* = F_pre × T_eval / (S_pre,total·c − I_pre,total)`로 보고한다. 분모가 0 이하이면 유한한 `H*`가 없다고 보고한다. `H*`가 평가 자료가 포괄하는 기간보다 길면 측정 범위 밖으로 명시한다.

## 4. A의 실행 순서와 정책 선택

A는 **위약 시뮬레이션 B보다 먼저 단독 실행**한다. 같은 머신에서 CPU 계측과 시뮬레이션을 동시에 돌리지 않는다.

### A1. Within C3

- 실제 봉인 C3 구현과 같은 모델·특징·10개 매듭을 사용한다.
- 창별 `fit` CPU 시간, 매듭별 `n_iter_`, 시험 구간 결정 수 `N_w`, 10개 모델의 일괄 `predict` CPU 시간, `κ` 보정 및 장부 추가 비용을 기록한다.
- `N_w`에는 모든 조각 결정을 포함한다. 규칙 경로가 선택된 결정에서도 반사실 AI 결정 `A_i` 계산에 추론이 필요하다.
- `OMP_NUM_THREADS=1` 등 기존 단일 스레드 설정과 CPU affinity를 확인하고, 각 구간을 CPU 시간 기준으로 3회 측정한다.

### A2. 사전 학습 C3

- v1 pre와 동일한 학습원을 미리 고정한다.
- 학습 CPU `F_pre`, 운영 추론·보정·장부 CPU `I_pre,total`, 시뮬레이션 이득 `S_pre,total`을 기록한다.
- 개발 40일 전체를 `T*=2.6 s`에서 집계하고, 운영 중 증분 기준과 생애주기 기준을 모두 계산한다.

### A의 산출물과 분기

- within이 앞 절의 온라인 비용 판정을 통과하면 within C3를 확증 후보로 둔다.
- within이 탈락하고 사전 학습 C3가 판정 기준을 통과하면 사전 학습 C3를 확증 후보로 둔다.
- **within과 사전 학습 C3가 모두 탈락하면 순이득을 확증할 정책은 없다.** 이 경우 B는 v2 봉인 정책인 within C3에 실행하되 사후 분석으로만 보고하고, v3 독립 트레이스 확증은 실행하지 않는다. 논문의 주 결과는 순비용 판정과 기여 분해로 한정하며 AI 우위 주장을 하지 않는다.

## 5. 위약 대조 B

A 결과로 대상 정책을 정한 뒤 개발 40일에서 해당 정책과 위약 3종을 각각 5개 고정 시드로 실행한다. 전환 규칙은 그대로 유지한다. 규칙 선택 빈도는 사후 진단 지표로 보고하며, 대조군을 맞추기 위해 전환 규칙을 수정하지 않는다.

1. `P_label`: 라벨을 섞어 학습해 조각별 예측 정보를 제거한다. 섞기 순서와 시드를 기록한다.
2. `P_draw`: 각 조각에 직전 30초 구간 조각들의 예측값 중 하나를 무작위로 할당한다. 미래 이벤트를 사용하지 않는다.
3. `P_shuffle`: 같은 30초 구간의 조각 사이에서 예측값을 섞는다. 뒤쪽 조각의 예측값도 사용될 수 있으므로 비인과적 위약이며, 실제 온라인 정책으로 해석하지 않는다.

비용이 낮을수록 좋다는 기준으로 다음을 보고한다.

- `C3 − P_shuffle`: 조각별 예측 정보의 효과를 진단하는 주 비교. C3가 P_shuffle을 이기면 조각별 정보의 유용성을 지지하는 강한 근거로 해석한다. 지거나 비기면 P_shuffle이 이용한 미래 정보 등의 영향 때문에 예측 정보의 무용성을 단정하지 않는다.
- `P_draw − P_label`: 예측값 분포·흩어짐 효과를 진단한다.
- `P_shuffle − P_draw`: 시점 효과를 진단한다.
- `P_label − rule`: 전환 구조와 위약 모델이 함께 만드는 나머지 차이를 진단한다.
- 전환이 있을 때의 `C3 − P_shuffle,C3`와 전환이 없을 때의 `AI − P_shuffle,AI`를 비교해 상호작용을 계산한다. 이를 순수한 인과적 기여도로 단정하지 않는다.

시드는 정확히 5개로 고정하고 결과를 본 뒤 늘리지 않는다. 시드별 결과 범위가 사전등록한 `±0.5%p` 경계에 걸치면 `판정 불가`로 보고한다. ‘AI 정보가 비용을 줄였다’고 쓰려면 `C3 − P_shuffle`가 비용 감소 방향 `−0.5%p` 이하이고, 그 절댓값이 같은 분모·비용 정의로 환산한 AI 경로 CPU 오버헤드의 `%p`보다 커야 한다. AI 경로 오버헤드는 A에서 선택된 정책의 `I`를 사용하고, within이면 `R=2τ`에서의 `F_within·τ/R`도 포함한다.

## 6. 독립 트레이스 확증: Copilot

Copilot 공개 자료는 호출 시각과 토큰 수를 포함하므로 BurstGPT와 동일한 입력 형식을 구성할 수 있는 우선 후보로 둔다. 원시 이벤트를 열기 전에는 공개 스키마와 이용 조건만 확인한다. A 결과로 확증 대상이 정해진 다음, 원시 이벤트를 보기 전에 `prereg-v3`를 고정한다.

`prereg-v3`에는 대상 정책, 자격 창, 토큰→바이트 변환, 솎기 및 특징 생성·제외 규칙, 평가지표, 비용 정의, 판정 경계, 통계 처리 규칙을 기록한다. 결과 확인 후 변환 규칙이나 판정 기준을 바꾸지 않는다. 결과는 ‘고정 변환 규칙으로 만든 독립 트레이스 평가’로 기술하며, 실제 메모리 할당 로그 또는 실제 allocator에서의 직접 검증이라고 부르지 않는다. A에서 두 정책이 모두 탈락하면 v3는 실행하지 않는다. v2 41일 자료에 추가 수행한 분석은 사후·탐색 분석으로 표시한다.

## 7. 문서 정합성

- 논문 §2와 프로젝트 지침에서 Fargate 가격 비율을 상대 비용 가중치이자 모델링 가정으로 기술한다. 실제 청구액이나 최대 RSS 감소를 의미한다고 쓰지 않는다.
- 구현과 다른 초기 계획(선확보, W–A 파레토, LSTM/1D-CNN, 지연시간 `L` 등)을 실제 기여처럼 남기지 않는다. 계획과 실제 구현의 차이는 변경 이력으로 구분한다.
- `jemalloc` 감쇠를 고정 타임아웃과 동일시하지 않는다. 직접 구현·검증하지 않았다면 별도의 고정 타임아웃 기준선으로만 설명한다.
- 관련 연구는 서버리스 keep-alive, FaaSCache, 학습 예측을 활용한 온라인 알고리즘 등 가장 가까운 문제 구조를 포함해 차이를 설명한다.
- 실행 후 판정 기준을 바꿔야 한다면 이유와 시점을 기록하고, 결과를 확인한 뒤 주요 기준을 소급 변경하지 않는다.
