# 사전 등록 v2 초안 — AI·규칙 결합 반납 정책의 봉인 확인 (2026-10-25)

> 상태: **초안**이다. 승인 조건은 두 가지다. (1) 3단계 측정으로 판정 T*를 정해 `exp/sealed_v2/tstar_eval.txt`에 적는다. (2) 연구자가 이 문서를 승인한다.
> 승인 전에는 v2 봉인 창으로 정책을 돌리지 않는다. 승인 뒤 `run_sealed_v2.sh`를 실행하고, 결과는 방향과 상관없이 이 문서의 기준으로 보고한다.
> 모든 수치는 유체 모델 시뮬레이션(시뮬)이다. v1은 `prereg-v1.md`·`sealed-results-v1.md`, 후보 개발은 `v2-dev-results.md`에 있다.

## 0. v1에서 이어지는 점
- v1 판정에서 H1(AI vs 고정 타임아웃)은 충족했다. H2(AI vs 2특징 규칙)는 반대 방향이었다(T* = 1초에서 규칙 쪽 비용이 낮았다).
- v1 탐색 결과 세 가지가 v2 설계를 정했다.
  - 같은 특징만 쓴 AI도 규칙에 졌다. 차이는 특징이 아니라 모델링·보정 방식에서 났다.
  - AI는 T* ≥ 3초에서 규칙보다 나았다.
  - 대체 장치가 없으면 최악 창이 크게 나빠졌다.
- v1 봉인 창(실제 131, 합성 40)은 v1 판정 뒤 v2 개발 데이터로만 썼다. v2 확인에는 쓰지 않는다.

## 1. 질문과 주장 범위
- 연구 질문: AI 생존 정책과 2특징 규칙을 그림자 장부로 골라 쓰는 결합 정책(C3)이, 같은 온라인 보정·대체 장치를 쓰는 2특징 규칙보다 실측 T*에서 비용이 낮은가?
- 판정 대상은 정책 비교다. C3는 규칙으로 돌아가는 장치를 포함하므로, 이득을 'AI 단독의 이득'이 아니라 'AI가 규칙에 더하는 몫'으로 쓴다.
- 판정 T*는 3단계에서 잰 실효 T*다(§3.3). 시뮬레이션의 다른 T*(0.3·1·3·10초)는 탐색으로 공개한다.
- 모집단은 'BurstGPT v2.0에서 자격 창이 있는 날 중 v1 표본에 들지 않은 41일'이다. 이 날들은 v1 표본 설계의 나머지라 무작위 표본이 아니다(§4.1). 결론을 BurstGPT 전체나 다른 서비스로 일반화하지 않는다.

## 2. 가설과 판정 기준
### 2.1 가설
| 가설 | 대상(독립 단위) | 비교 | 검정 | 충족 조건 |
|---|---|---|---|---|
| H1v2 (1차) | v2 봉인 실제 창 41개 | C3 vs 규칙-온라인+대체 | 양측 정확 부호 검정 | p < 0.05, 승 > 패 |
| H2v2 (2차) | 같은 창 | C3 vs 고정-온라인 | 양측 정확 부호 검정, Holm(2) | 보정 p < 0.05, 승 > 패, 후퇴 비율 ≤ 10% |
| H3v2 (2차) | 합성 확인 40개(시드 201~205) | C3 vs 규칙-온라인+대체 | 양측 정확 부호 검정, Holm(2) | 보정 p < 0.05, 승 > 패 |
- 판정 T*는 셋 모두 실효 T* 하나다. H1v2에는 보정을 하지 않는다. 2차 가설 둘은 Holm(2)로 보정한다.

### 2.2 계산 정의 (v1 §2.2와 같다, `prereg_v2_analysis.py`)
- 창 평가값 Δ_p = (C_p ÷ C_고정-온라인 − 1) × 100이다. 기준 비용이 0이면 Δ = 0으로 둔다(실행 코드 규칙).
- d(A, B) = Δ_A − Δ_B(%p)다. d < −0.5면 승, d > +0.5면 패, 그 밖은 무승부다.
- 부호 검정은 무승부를 뺀 단위로 한다. 후퇴 비율 = 패 ÷ (승 + 무 + 패)다.
- 학습 정답이 한 종류뿐인 창과 실행 오류가 난 창은 그 T*에서 빼고 개수와 이유를 보고한다.

### 2.3 결과별로 쓸 문장 (미리 고정)
- H1v2 충족: "v1에서 쓰지 않은 BurstGPT 41일의 실측 T* = X초에서, AI 생존 정책과 2특징 규칙을 그림자 장부로 고르는 결합 정책의 유체 모델 비용이 같은 보정의 2특징 규칙보다 낮았다."
- H1v2 미충족, 차이 검출 못 함: "…2특징 규칙과의 차이를 확인하지 못했다."
- H1v2 미충족, 반대 방향(p < 0.05, 패 > 승): "…2특징 규칙보다 비용이 높았다." (v1에서 미리 정하지 않아 고쳐 쓴 경우를 막으려고 넣었다.)
- H2v2·H3v2도 같은 세 가지 문장 틀로 쓴다.
- 어떤 결과에서도 쓰지 않는 문장: "AI 단독이 규칙보다 낫다", "모든 T*에서 낫다", "BurstGPT 밖에서도 낫다", "실제 할당기에서 낫다"(3단계 재생 결과는 따로 보고한다).

### 2.4 탐색 (판정 없음)
- 다른 T*에서의 같은 비교, v1 주 AI vs 규칙(v1 H2의 새 데이터 재현), C1·C2·C4 vs 규칙, 합성 요인 효과(시드 블록 짝 Wilcoxon), C3가 규칙을 쓴 비율.

## 3. 방법 (고정)
### 3.1 공통
- 설정은 v1의 `exp/frozen.json`과 같다. 특징 f15, 온라인 보정 창 900초, 주기 30초, T_cap = min(300, 20·T*), 묶음 최소 2%·20조각이고, 대체 장치는 W 300초, ε 0, H 0이다.
- 프로토콜은 within(창마다 학습 50 / 검증 25 / 시험 25)만 쓴다. 생존 모델은 HistGradientBoosting이다(매듭 10개, 최대 120회, 시드 0, OMP_NUM_THREADS=1).

### 3.2 정책
| 정책 | 정의 | 역할 |
|---|---|---|
| 고정-온라인 | 반납 시점 하나를 장부로 30초마다 고른다 | 기준 |
| 규칙-온라인+대체 | 특징 1~2개 4분위 칸별 반납 시점을 장부로 고르고, 고정-온라인으로 대체한다 | 비교군 |
| **C3 AI→규칙대체** | v1 주 AI(AI생존κ-온라인+대체)와 규칙-온라인+대체 중 최근 300초 장부 비용이 낮은 쪽을 쓴다 | **주 후보** |
| v1 주 AI, C1, C2, C4 | `v2-dev-results.md` §1 | 탐색 |
- 코드는 `paperexp3.py`의 `evaluate3`다. 개발 트레이스에서 v1 정책 값이 v1 결과와 정확히 같음을 확인했다.

### 3.3 판정 T* (측정 전에 정한 규칙)
- 3단계 `stage3.sh`의 `chunkpool tstar` 결과에서 1 MiB 청크, MADV_DONTNEED, 시스템 기본 THP, batch 16 조건의 실효 T* 중앙값(3회 실행을 합친 값)을 유효숫자 2자리로 반올림한다.
- 실효 T* = (반납 + 재확보 CPU 초/MiB) × 9.107 × 1024다. 9.107은 AWS Fargate의 vCPU-시 ÷ GB-시 가격 비율이다(계산, 가격 확인 필요).
- 이 규칙은 `stage3_summary.py`·`stage3.sh`에 v2 후보 개발 결과를 보기 전에 적었다.
- 측정은 연구자의 WSL에서 한다. 측정값과 `env.txt`를 승인 커밋에 함께 넣는다.

## 5. 개발 결과 요약 (선택 근거, `v2-dev-results.md`)
- 선택 규칙은 결과를 보기 전에 정했고, 그 규칙으로 C3가 뽑혔다. C1은 후퇴 비율 조건으로 빠졌다. C2와 C3는 규칙을 이긴 T* 수가 같았고, d 중앙값 평균에서 C3가 앞섰다.
- C3 vs 규칙 (v1 R 집합): T* = 0.3초 13/36/1(p = 0.0018), 1초 10/37/6(p = 0.45), 3초 34/15/5(p = 2.4×10⁻⁶), 10초 36/9/9(p = 6.6×10⁻⁵)였다.
- 같은 비교를 v1 R의 BurstGPT 창으로 좁히면 T* = 1초 9/25/5(p = 0.42), 3초 20/15/5(p = 0.004), 10초 23/8/9(p = 0.020)였다.
- C3는 모든 개발 묶음과 T*에서 규칙보다 유의하게 나쁜 적이 없었다.

## 6. 검정력 (계산·추정)
- 무승부가 아닌 단위가 30개면, 승 21개 이상(70%)이어야 p < 0.05다(계산). 25개면 18개 이상(72%)이고, 35개면 24개 이상(69%)이다.
- 개발 데이터의 BurstGPT R 창 비율을 그대로 옮기면 기대 결과는 이렇다(추정).
  - T* = 1초: 9/25/5. 무승부가 아닌 단위가 14개뿐이라 H1v2는 충족되기 어렵다.
  - T* = 3초: 20/15/5. 충족 가능성이 높다.
- 따라서 결과는 판정 T*에 크게 달려 있다. 판정 T*의 규칙은 측정 전에 고정했다(§3.3).

## 7. 실행 절차
- 승인 뒤 `./run_sealed_v2.sh`를 실행한다.
  - (1) v2 봉인 창 일정을 만든다.
  - (2) 합성 40개를 만든다.
  - (3) `paperexp3.py`를 묶음(창 6개)으로 나눠 실행한다. T* 목록은 판정 T* + 0.3·1·3·10이다. 묶음마다 새 임시 파일에 쓰고 종료 코드를 확인한 뒤 옮긴다.
  - (4) 원래 순서대로 이어 붙인다.
  - (5) `prereg_v2_analysis.py`로 판정한다.
- 백그라운드 작업 시간 제한 때문에 끝나지 않으면 같은 명령을 다시 실행해 남은 묶음만 돌린다. 이 방식은 v1에서 단일 실행과 바이트 단위로 같음을 확인했다.
- 예상 실행 시간은 2코어에서 약 30~60분이다(추정, 개발 실행 속도로 계산).

## 9. 미리 밝히는 한계
- 주 후보는 v1 봉인 창(개발 데이터로 전환)에서 골랐다. 그 데이터에서 본 결과가 확인 데이터에서 재현되지 않을 수 있다.
- C3의 이득은 시간대마다 AI와 규칙 중 나은 쪽을 고른 결과라, AI 단독의 이득과 구분된다.
- 확인 데이터는 BurstGPT 한 서비스이고 무작위 표본이 아니다. Azure 2024는 남은 날이 없다.
- 판정 T*는 가격 비율(Fargate) 가정에 달려 있다. 실제 운영 비용 구조가 다르면 해석이 달라진다.
- 유체 모델에는 단편화가 없다. 실제 청크 풀에서의 비용은 3단계 재생으로 따로 확인한다.
