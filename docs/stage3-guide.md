# 3단계 측정 안내 — 실효 T*와 청크 풀 재생 (2026-10-24)

> 목적: 유체 모델의 비용(재확보 MiB + 낭비 MiB·초 ÷ T*)이 실제 메모리에서 어떤 T*에 해당하는지(실효 T*) 재고, 같은 정책 결정을 실제 청크 풀에서 실행해 유체 모델의 계산이 맞는지 확인한다.
> 이 측정은 봉인 판정(v1)을 바꾸지 않는다. 실효 T*는 v2 사전 등록의 판정 T*를 정하는 데 쓴다(`prereg-v2-draft.md`).

## 1. 무엇을 재는가
- **실효 T\***: 놀고 있는 1 MiB를 반납했다가 다시 쓰는 데 드는 CPU 시간 c(초/MiB)를, 같은 1 MiB를 1초 붙잡아 두는 메모리 비용과 맞바꾼 값이다.
  - T* = c × (vCPU 1시간 가격 ÷ GB 1시간 가격) × 1024이다.
  - 가격 비율 기본값 9.107은 AWS Fargate(리눅스 x86, us-east-1)의 $0.04048/vCPU-시 ÷ $0.004445/GB-시다(계산, 가격은 확인 필요).
  - c는 반납(madvise) CPU와 다시 쓸 때의 페이지 폴트·0 채우기 CPU를 더한 값이다.
- **청크 풀 재생**: 요청 본문을 청크(1 MiB 또는 2 MiB) 단위로 주는 풀에서, 유체 모델 정책(고정-온라인, 규칙-온라인+대체, v1 주 AI)이 정한 반납 시점대로 실제로 반납·재확보한다.
  - 재확보량은 유체 모델과 같은지 확인한다.
  - CPU 시간은 실제로 잰다.
  - 실제 RSS가 장부상 상주량과 맞는지(반납이 실제로 메모리를 돌려주는지) 확인한다.

## 3. 출력 읽는 법
### 3.1 `tstar_summary.txt`
- 행마다 (청크, 반납 방식, THP, 한 번에 반납하는 청크 수)별로 반납·재확보 CPU(µs/MiB), MiB당 페이지 폴트, 반납 직후 RSS 감소 비율, 실효 T*를 보인다.
- 반납 방식:
  - `dontneed`(MADV_DONTNEED): 즉시 메모리를 돌려준다.
  - `free`(MADV_FREE): 메모리 압박이 없으면 RSS가 줄지 않는다. 그래서 비용 비교에는 쓰지 않는다.
  - `remap`: 같은 주소에 새 매핑을 덮는다.
- THP:
  - `default`: 시스템 설정을 따른다. WSL의 보통 설정(madvise)이면 4 KiB 페이지다.
  - `on`: MADV_HUGEPAGE로 2 MiB 페이지다. 1 MiB 청크를 반납하면 큰 페이지가 쪼개진다.
- 판정용 T*(`tstar_eval.txt`)는 1 MiB 청크, `dontneed`, `default`, batch 16의 실효 T* 중앙값을 유효숫자 2자리로 반올림한 값이다. 이 규칙은 측정 전에 v2 사전 등록 초안에 적었다.

### 3.2 `replay_summary.txt`
- 열의 뜻:
  - 재확보 MiB(실측/유체): 두 값이 같아야 한다.
  - CPU 초: 반납 + 재확보, 평가 구간 조각만 센다.
  - RSS 오차 max: 실제 RSS − 장부 상주량, MiB.
  - 실제 비용 = CPU 초 × 9.107 × 1024 + 낭비 MiB·초다.
  - 유체 예측 = 재확보 MiB × T* + 낭비 MiB·초이고, T*는 내보낼 때 쓴 값이다.
  - 함축 T* = CPU 초 ÷ 재확보 MiB × 9.107 × 1024다.
- 정책: `fixed`(고정-온라인), `rule`(규칙-온라인+대체), `ai`(v1 주 AI), `never`(반납 안 함), `now`(즉시 반납)이다.
- 확인할 것:
  - (1) RSS 오차가 수 MiB 이내인지 본다(반납이 실제로 메모리를 돌려준다).
  - (2) 함축 T*가 `tstar_eval.txt`와 비슷한지 본다(비용 모델이 실제 사용 패턴에서도 성립한다).
  - (3) 실효 T*로 내보낸 결정에서 정책 순서가 실제 비용과 유체 예측에서 같은지 본다.

## 4. 컨테이너 동작 확인 (참고, 측정값 아님)
- 클라우드 컨테이너(2코어, 다른 계산과 함께 돌림)에서 `QUICK=1`로 끝까지 돌아감을 확인했다.
- `dontneed`/`default`에서 RSS 오차는 0.1 MiB였고, 재생의 재확보 MiB는 유체 모델 값과 같았다.
- 컨테이너 값(1 MiB, dontneed, default, batch 16)은 재확보 약 590 µs/MiB, 실효 T* 약 6초였다(컨테이너 실측, 다른 계산과 CPU를 나눠 써서 부풀었을 수 있다). 앞서 계산한 1.6~2.5초(THP 기본)와 차이가 커서 대상 환경 측정이 필요하다.

## 5. 한계
- 재생은 시간을 빨리 감는다. 백그라운드 회수(kswapd, khugepaged)와 메모리 제한(cgroup) 아래의 MADV_FREE 동작은 재지 않는다.
- 비용은 CPU 시간과 메모리를 가격으로 맞바꾼 값이다. 지연 예산(D_max)을 기준으로 한 해석은 따로 해야 한다.
- 요청 크기를 청크 배수로 올림하므로 재생의 부하는 v1 시뮬레이션의 부하와 조금 다르다.
