# 시뮬레이션 재실험 결과 v1 — 학습 기반 버퍼 반납 정책 (유체 모델, 2026-10-24)

> 상태: 예비 결과다. 모든 수치는 유체 모델 시뮬레이션(시뮬) 값이며 실제 할당기·C++ 청크 풀의 결과가 아니다.
> 'AI 생존' 변형은 1·2차 실행의 시험 구간 결과를 본 뒤 추가했다(탐색적). 이 변형의 수치는 확인 근거로 쓰지 않고 봉인 데이터에서 다시 잰다.
> 설계는 paper-design-v1.md, 도구 사용법은 membench-guide.md를 따른다. 원자료는 membench.tar.gz의 exp/res/*.csv다.

## 0. 요약

- T* = 0.3·1초에서 'AI+대체'는 검증 구간으로 고른 고정 타임아웃보다 비용을 중앙값 7.5%·13.1% 줄였다. 0.5%p 넘게 나빠진 트레이스는 없었다(9개 중 6승 3무, 10개 중 7승 3무, 부호 검정 p = 0.031·0.016, 시뮬).
- T* = 1초의 이득은 주로 유휴 메모리에서 나왔다. 고정 정책이 메모리를 쥐는 6개 트레이스에서 평균 유휴 보유량은 중앙값 28.5% 줄었고 재확보량은 중앙값 5.3% 늘었다(시뮬).
- 미리 정한 AI는 2특징 규칙(+대체)을 일관되게 이기지 못했다. T* = 1초에서 3승 4무 3패, T* = 3초에서 1승 1무 8패(p = 0.039, 규칙 우세)였다. T* = 1초에서 AI는 실제 트레이스 3개(az_conv, bg_q99, bg_q100)에서 이겼고 규칙은 합성 트레이스 3개에서 이겼다.
- 탐색적 'AI 생존+대체'는 규칙(+대체)과 비교해 T* = 1초에서 5승 4무 1패, T* = 3초에서 4승 2무 4패였다(사후 추가 변형).
- 대체 장치가 없으면 AI는 최악 +42.4%(bg_q90, T* = 3), 규칙은 최악 +47.5%(bg_q100, T* = 1)였다. 대체 장치를 붙이면 T* ≤ 3초에서 최악이 +2.1%였고, T* = 10초에서는 +3.7%(AI)·+6.7%(AI 생존)·+9.0%(규칙)가 남았다.
- PSK 결정적은 모든 T*에서 중앙값이 고정 타임아웃보다 나빴다(+0.6~+8.9%).
- 트레이스 단위 일반화: 다른 트레이스로 고른 고정 타임아웃은 중앙값 +6.6~+13.4% 나빴다. 다른 트레이스로 학습한 분류기에 대상 트레이스의 검증 구간으로 칸별 타임아웃만 다시 맞추고 대체 장치를 붙이면 T* = 1초에서 중앙값 −9.3%(8승 2무 0패, p = 0.008)였다.
- 순열 중요도를 잰 6개 트레이스 × T* 2개의 모든 경우에서 1위는 조각 위치 특징('수준' 또는 '높이')이었다. 유입·도착 수 특징의 AUC 감소가 0.05를 넘은 것은 합성 주기 트레이스뿐이었다.
- 분류기 시드(0·1·2)를 바꿔도 AI+대체 중앙값은 T* ≤ 3초에서 1%p 안에서 움직였고, 고정 대비 승/무/패는 세 시드에서 같았다(3.8절).

## 1. 질문과 범위

- 연구 질문(paper-design-v1 §1) 가운데 이 실험은 "같은 비용 조건에서 학습 예측이 고정 타임아웃과 단순 규칙보다 비용을 얼마나 줄이는가"만 다룬다. 실제 할당기와 메모리 제한 환경(설계 §3.2·§4)은 다루지 않는다.
- 비교는 손익분기 시간 T*를 매개변수로 둔 비용 모델 안에서 한다. T*가 작다는 사실만으로 메모리 부족을 입증하지 않는다.

## 2. 방법

### 2.1 유체 모델과 비용
- 요청 본문은 도착부터 처리 완료(또는 마감 폐기)까지 살아 있다고 보고 사용량 D(t)를 만든다. D(t)를 높이 조각으로 나누면 조각마다 놀기 시작한 시각 ts, 다시 쓰일 때까지의 놀이 시간 g, 두께 h, 재사용 여부 r이 생긴다. 끝까지 다시 쓰이지 않는 조각은 r = 0이다.
- 정책은 조각마다 반납 시각 T를 정한다. 비용 = h·min(g, T)/T* + h·[r ∧ g > T]이다. 앞 항은 낭비(MiB·s)를 T*로 나눈 값, 뒤 항은 재확보량(MiB)이다.
- 단편화는 없다고 본다. 미리 잡아 두기는 재확보량을 줄이지 못하므로 결정 변수는 반납 시점뿐이다.
- 기준은 검증 구간으로 고른 고정 타임아웃이다. 표의 %는 같은 시험 구간에서 이 기준 대비 비용 변화이고, %p는 이 비율끼리의 차이다.

### 2.3 데이터 분리
- 트레이스마다 시간 순으로 학습 50% / 검증 25% / 시험 25%로 나눴다. 조각은 놀기 시작한 시각으로 구간에 넣었다. 시험 구간 비용은 시험 구간에서 놀기 시작한 조각만 센다.
- 엠바고: 학습·검증 구간 끝 300초 안에 놀기 시작한 조각은 그 구간에서 뺐다.
- 관찰 절단: 학습·검증의 g는 그 구간 끝까지 관찰한 값만 썼다. 구간 끝까지 다시 쓰이지 않은 조각은 '끝까지 놀았고 그 뒤 다시 쓰인다'로 두었다. 그래서 학습·검증에서 고르는 타임아웃은 0~300초로 제한했다.
- 분류기는 학습 구간에서만 학습했다. 결정 매개변수(고정 타임아웃, 규칙의 특징 조합과 칸별 타임아웃, AI 점수 칸별 타임아웃, PSK의 λ, AI 생존의 κ, 대체 장치의 W·ε·H)는 검증 구간에서 골랐다.
- 교차 적합: 검증 구간을 시간 순 두 쪽으로 나눠 한쪽에서 맞춘 값을 다른 쪽에서 평가했다. 규칙의 조합 선택과, 대체 장치 선택에 쓰는 검증 구간의 AI·규칙 결정을 이 방식으로 만들었다. AI 생존의 검증 구간 결정은 κ 하나를 검증 전체로 고른 값이다(교차 적합하지 않았다).
- 시험 구간은 모든 선택을 확정한 뒤 한 번 평가했다.
- 특징 정규화: 유입률·도착 수·사용량을 그 트레이스 학습 구간의 평균으로 나눴다.

### 2.4 정책

| 정책 | 결정 방식 | 학습 / 선택 |
|---|---|---|
| 고정 타임아웃 | 모든 조각을 T초 뒤 반납한다 | T: 검증(0과 10⁻³~300초 로그 간격 101점) |
| 2특징 규칙 | 특징 1~2개를 각각 검증 구간 4분위 칸으로 나누고 칸 조합마다 타임아웃을 둔다 | 조합 55가지 중 검증 교차 적합으로 선택, 칸별 T는 검증 |
| AI | 그래디언트 부스팅(sklearn HistGradientBoosting, 200회, 잎 31)으로 P(g > T*)를 예측하고 점수 10분위 칸마다 타임아웃을 둔다 | 분류기: 학습(두께 가중), 칸 경계·칸별 T: 검증 |
| AI 생존(탐색적) | 매듭 τ 10개(0.01~300초)마다 P(g > τ) 분류기(120회)로 단조 생존 곡선 S(τ)를 만들고, 조각마다 E[min(g, T)]/T* + S(T)가 최소인 T(0 또는 매듭)에 κ를 곱한다 | 분류기: 학습(T*와 무관한 모델 하나), κ ∈ {0.5, 0.7, 1, 1.4, 2}: 검증 |
| PSK 결정적 | 분류 확률 ≥ 0.5이면 'g ≥ T*' 예측으로 보고 λT*에, 아니면 T*/λ에 반납한다(Purohit·Svitkina·Kumar, NeurIPS 2018의 대응) | λ ∈ {0.1, 0.2, 0.3, 0.5, 0.7, 1}: 검증 |
| PSK 무작위 | 반납 시각 τ ~ e^{τ/T*} / (T*(e^{K/T*} − 1)), τ ∈ [0, K], K = λT* 또는 T*/λ이다. 기대 비용을 닫힌 식으로 계산한다 | λ: 검증 |
| +대체 | 2.5절의 그림자 장부 전환을 붙인다 | W·ε·H: 검증 |
| 오라클 | g를 알고 r ∧ g < T*이면 쥐고, 아니면 바로 반납한다 | 구현 불가, 유체 모델 안의 하한 |
| 즉시 반납·반납 안 함 | T = 0, T = ∞ (참고값) | — |

- 특징 10개는 조각이 놀기 시작한 시각까지의 정보만 쓴다. 사용량(놀기 시작한 직후의 D), 높이(조각 가운데가 그 D 위로 떨어진 거리), 수준(조각 가운데의 절대 높이 = 사용량 + 높이), 유입 1·10·60초(바이트율), 도착 수 1초, 이전 놀이(같은 1 MiB 높이에서 직전에 끝난 놀이 시간, log10), 최근 10·60초 최고 사용량 − 수준이다.

### 2.5 대체 장치(그림자 장부)
- D(t)는 반납 정책과 무관하게 관찰되므로, 결정 대상 조각마다 AI와 고정 정책이 각각 냈을 비용(낭비는 쥔 시간이 끝날 때, 재확보는 다시 쓰일 때 기록)을 같은 장부에 쌓는다. 이 값은 같은 입력에 대한 반사실적 추정치다.
- 결정 시각마다 최근 W초의 장부 비용이 AI > (1 + ε) × 고정이면 고정 정책을 쓴다. H > 0이면 전환 뒤 최소 H초를 유지한다.
- 민감도: W ∈ {60, 300, 900}초, ε ∈ {0, 0.05}, H ∈ {0, 60}초를 모두 시험 구간에서 따로 쟀다. 본 결과(+대체)는 검증 구간 비용이 가장 작은 조합 하나를 쓴다.
- 손해 구간: 사후에 AI가 고정보다 5% 넘게(그리고 시험 총비용의 0.2% 넘게) 나빴던 1분 칸이 2개 이상 이어진 구간이다. 전환 지연은 손해 구간 시작부터 고정 정책이 처음 켜질 때까지의 시간이고, 놓침은 구간 안에서 한 번도 켜지지 않은 경우다.

### 2.6 트레이스 단위 일반화(LOTO)
- 한 트레이스를 빼고 나머지 9개 트레이스의 학습 구간으로 분류기를 학습했다(트레이스마다 같은 총 무게).
- 무보정: 나머지 트레이스의 검증 구간으로 점수 칸 경계·칸별 타임아웃·고정 타임아웃을 골라 뺀 트레이스의 시험 구간에 적용했다.
- 국소 보정: 분류기는 그대로 두고 뺀 트레이스의 검증 구간으로 칸별 타임아웃만 다시 골랐다. '+대체'는 같은 검증 구간으로 W·ε·H를 골랐다. 뺀 트레이스의 학습 구간은 쓰지 않았다.
- 기준은 뺀 트레이스의 검증 구간으로 고른 고정 타임아웃(트레이스 안 실험의 기준과 같다)이다.

### 2.7 집계와 검정
- 트레이스마다 기준 대비 비용 변화(%)를 구하고 트레이스 간 중앙값·최악(최대)을 보고한다.
- 승/무/패는 차이가 ±0.5%p 안이면 무승부로 센다. 부호 검정은 무승부를 뺀 양측 검정이다. 트레이스를 표본으로 보는 서술용 검정이며 다중 비교를 보정하지 않았다.
- 시험 구간 길이는 트레이스마다 약 900초다.

### 2.8 실행 기록
- 1차: 고정, 2특징 규칙, AI, AI+대체, PSK 2종, 오라클을 쟀다.
- 2차: 공정성을 위해 '2특징+대체'를 더했다. 1차와 공통인 정책의 값은 같았다.
- 3차: 2차 결과에서 T* = 3초에 규칙이 AI를 이긴 것을 본 뒤 'AI 생존'(+대체, LOTO 포함)을 더했다. 공통 정책의 값은 같았다.
- 4차: 비용 분해(재확보량·낭비)를 출력하도록 고친 코드로 다시 돌려 3차의 within.csv·fallback.csv와 바이트 단위로 같음을 확인했다. 시드 1·2 실행을 더했다.

## 4. 분석

### 4.1 AI가 고정 타임아웃보다 나은 조건
- 이득은 T* = 0.3~1초에 모였다. T* = 1초에서 AI+대체는 7개 트레이스에서 이겼고 진 트레이스가 없었으며, 이득의 대부분은 평균 유휴 보유량 감소(중앙값 −28.5%)였다. 재확보량은 중앙값 +5.3%로 조금 늘었다. 따라서 T* = 1초의 AI는 '곧 다시 쓰일 조각만 쥐고 오래 놀 조각을 일찍 내놓는' 방향으로 고정 타임아웃을 고쳤다고 해석한다(추론, 3.3절 분해 근거).
- T* = 0.3초에서는 방향이 반대였다. 재확보량을 줄이고(−21.0%) 유휴 보유를 늘렸다(+18.2%). 고정 타임아웃이 0.02~0.11초로 짧아 대부분을 바로 내놓는 조건에서, AI는 곧 다시 쓰일 조각을 골라 더 오래 쥐었다(추론).
- T* = 10초에서는 오라클 차이가 −21.3%로 남았는데 어떤 학습 정책도 그 차이를 메우지 못했다. 분류 AUC는 0.93~0.97로 높았다. 검증으로 고른 고정 타임아웃(4~15초)이 이미 짧은 놀이 조각을 대부분 다시 쓰일 때까지 쥐므로, 남은 결정은 소수의 긴 놀이 조각을 일찍 내놓는 것뿐이고, 그 이득(긴 조각마다 T/T* 만큼)과 잘못 내놓은 짧은 조각의 손해(재확보 1)가 상쇄된다고 추정한다(추정, 검증하지 않았다).
- 절대량은 작았다. T* = 1초에서 AI+대체가 줄인 평균 유휴 보유량은 트레이스당 0.4~3.2 MiB였다. 고정 타임아웃이 이미 '반납 안 함'의 유휴 보유(21~89 MiB)를 1~6 MiB로 줄였기 때문이다(3.3절). 이 실험의 부하(평균 살아 있는 본문 0.0~17.6 MiB)에서 AI의 기여는 상대적으로는 크지만 절대적으로는 MiB 단위다.

### 4.2 단순 규칙 대비 — AI가 더하는 것
- 순열 중요도에서 조각 위치('수준' 또는 '높이') 하나가 대부분의 순위 정보를 냈다(3.6절). 이 경우 위치 특징 하나를 4분위로 자른 규칙이 신호의 큰 몫을 잡는다. 미리 정한 AI가 규칙과 자주 비긴 이유를 이것으로 설명한다(추론).
- AI가 이긴 경우는 두 종류였다. (가) 규칙이 검증 구간에서 아무 칸도 못 찾은 경우(bg_q99, T* = 1초: 규칙 +0.0%, AI −12.6%), (나) 규칙이 검증에 맞춘 칸이 시험에서 어긋난 경우(bg_q100, T* = 1초: 규칙 단독 +47.5%, 대체 후 +0.0%, AI −17.0%)다. (가)는 4분위 칸이 짧은 놀이 조각의 소수 집단을 다른 조각과 섞는 반면 학습 점수의 10분위 칸은 그 집단을 몇 칸에 모아 칸별 타임아웃이 그 집단만 쥘 수 있게 한다는 것으로 설명한다(추론, 칸 순도를 직접 재지 않았다).
- 규칙이 이긴 경우는 합성 트레이스 3개(T* = 1초)와 T* = 3초 전반이었다. 합성 트레이스에서는 순위 정보가 특징 1~2개에 몰려 있었고(syn_periodic: 수준·유입10s), 규칙도 바로 그 조합(수준×유입10s)을 골랐다. 이 경우 규칙이 AI와 같거나 낫다고 본다(추론).
- T* = 3초에서 규칙이 더 강했던 이유는 이 실험으로 가리지 못했다(확인 필요). 차이는 bg_q90(규칙 −15.4%, AI+대체 +1.3%), bg_q100(−10.6 vs −3.5), az_conv(−12.8 vs −6.8), bg_q99(−12.5 vs −7.2)에서 컸고, syn_poisson에서는 AI가 앞섰다(−11.4 vs −0.0). T* = 3초에서 규칙이 고른 조합 10개 중 7개가 '수준'을 포함했다.
- 같은 특징·같은 학습기를 쓰고 결정 단계만 바꾼 탐색적 AI 생존이 T* = 3초의 격차를 줄였다(규칙 대비 4승 2무 4패, AI+대체 대비 7승 1무 2패). 따라서 약한 고리는 특징보다 '점수 10분위 칸 + 검증으로 맞춘 칸별 타임아웃'이라는 결정 단계라고 추론한다. 생존 모델은 T*마다 따로 학습하지 않고 한 모델로 모든 T*의 반납 시점을 정하므로, 실행 중 T*가 바뀌는 환경(메모리 압박이 변하는 환경)에 맞는 구조다(추론). 다만 κ는 검증에서 격자 끝(2가 13번, 0.5가 10번)이 39경우 중 23번 선택됐다. 생존 곡선의 보정이 치우쳐 있다는 뜻이다(추론). 사후 추가이므로 이 결과로 우열을 주장하지 않는다.

### 4.3 실패 원인 — 검증에 맞춘 결정 문턱이 시간에 따라 어긋난다
- bg_q90(T* = 3초)에서 긴 놀이 비율은 학습 34.6% → 검증 23.0% → 시험 11.2%로 줄었고 유입률은 늘었다. 검증에서 '빨리 내놓기'(T = 0~0.18초)로 정한 점수 칸 6~8은 검증에서 긴 놀이가 36~82%였지만 시험에서는 3.8~15.6%였고, 시험 두께의 52.6%(검증 21.5%)를 차지했다. AI는 몇 초 안에 다시 쓰일 메모리를 바로 내놓았다. 같은 사례의 AUC는 0.81로 다른 트레이스와 비슷했다. 따라서 실패는 순위(분류)보다 순위를 반납 시점으로 바꾸는 문턱의 보정에서 생겼다고 판단한다(추론, 3.7절 근거).
- 규칙의 bg_q100 실패도 같은 모양이다. 검증에서 −8~−10%였던 '수준' 기반 조합이 시험에서 모두 +36~+50%였다.
- BurstGPT 1시간 창은 시간 안에서 크게 변했다(bg_q99: 도착 9,024 / 962 / 1,264건, bg_q75: 803 / 66 / 62건). 시간 순 분리는 이 변화를 그대로 검증·시험 사이에 남긴다. 실제 운영에서도 같은 변화가 생기므로 이 실패는 실험 결함이 아니라 방법이 다뤄야 할 조건이다(판단).
- 그림자 장부는 모든 조각의 실제 g를 정책과 무관하게 관찰한다. 그래서 칸별 문턱을 최근 창의 장부로 계속 다시 맞추는 온라인 보정이 탐색 없이 가능하다(추론, 구현하지 않았다). 이것이 프로젝트 방법 3(실패 학습)의 직접적인 구현이다.

### 4.4 대체 장치의 역할과 한계
- 대체 장치는 이득의 원천이 아니라 안전망이었다. T* ≤ 3초에서 AI 단독과 AI+대체의 중앙값 차이는 0.4%p 이하였고, 최악은 AI +42.4% → +2.1%, 규칙 +47.5% → +0.0%로 줄었다.
- 민감도 표에서 W = 300초, ε = 0, H = 0이 평균(−6.1%)과 최악(+2.1%) 모두 가장 좋았다. W = 60초는 자주 전환했고(중앙 12회) 최악이 +9.1%였다. W = 900초, ε = 0.05는 손해 구간 11개 중 5개를 놓쳤다. 창이 짧으면 잡음에 반응하고 길면 늦다는 일반적 상충과 맞는다(해석).
- T* = 10초에서 최악 +3.7~+9.0%가 남았다. 긴 타임아웃에서는 낭비가 쥔 시간이 끝날 때 장부에 들어가 판단이 늦고, 정책 간 차이가 창 안의 잡음과 비슷한 크기라고 추정한다(추정).

### 4.5 PSK가 불리한 이유
- PSK의 반납 시점은 T*의 고정 배수(λT* 또는 T*/λ)다. 검증으로 고른 고정 타임아웃은 그 트레이스의 놀이 시간 분포에 맞춰져 T*와 크게 다를 수 있다(예: 부하가 낮은 BurstGPT 창에서 0초, 합성 트레이스 T* = 1초에서 0.48~0.8초). 이때 '짧다'고 예측한 조각을 T*/λ ≥ T*까지 쥐는 PSK의 가지가 데이터에 맞춘 타임아웃보다 비싸다(추론). 검증은 λ = 0.1을 39경우 중 13번 골랐다.
- PSK는 오프라인 최적 대비 최악 경쟁비를 보장하는 알고리즘이고 분포 아래 기대 비용을 최소화하지 않는다. 이 결과는 PSK의 보장과 모순되지 않는다. 무작위 판이 결정적 판보다 나았다(T* = 1초 7승 1무 2패).

### 4.6 트레이스 사이 이전
- 다른 트레이스로 고른 고정 타임아웃이 중앙값 +6.6~+13.4% 나빴으므로 좋은 타임아웃은 트레이스마다 다르다.
- 다른 트레이스로 학습한 분류기의 점수는 대상 트레이스에서도 쓸 만했다. 칸별 타임아웃만 대상 트레이스의 검증 구간으로 다시 맞추면 T* = 1초에서 −9.3%로, 대상 트레이스 학습 데이터를 쓴 트레이스 안 결과(−13.1%)의 약 70%였다. 무보정 AI는 최악 +14.2~+70.6%로 안전하지 않았다.
- 정리하면 순위(분류기)는 옮겨지고 문턱(칸별 타임아웃)은 옮겨지지 않는다(판단). 배포 형태로는 '미리 학습한 분류기 + 현장에서 장부로 문턱 보정'이 맞다(추론).

### 4.7 T*의 현실 범위 (계산)
- T* = C_재확보 / C_유지(초당)이다. 재확보 비용을 재확보 CPU 시간으로, 메모리와 CPU 가격을 공용 클라우드 단가로 두면 T* = (1 MiB 재확보 시간) × 1,024 MiB/GB × (vCPU 초 단가 / GB 초 단가)다.
- AWS Fargate(Linux/x86, 미국 동부) 단가는 vCPU 초당 $0.000011244, GB 초당 $0.000001235로 비가 9.10이다(AWS 가격표, 2026-10-24 확인).
- WSL 실측 재확보 시간은 THP 기본에서 1 MiB당 0.17~0.27 ms, THP on(2 MiB 이상)에서 0.037~0.10 ms였다(membench-guide §7.4, 실측).
- 계산 결과 T*는 THP 기본에서 1.6~2.5초, THP on에서 0.34~0.97초다(계산). 반납 CPU와 재확보 지연이 빠졌으므로 C_재확보를 낮게, 따라서 T*를 낮게 잡은 값이다.
- 이 가격 비에서는 AI가 고정보다 나았던 T* = 0.3~1초와 규칙이 강했던 3초가 모두 현실적인 범위에 든다. 다만 다른 프로세스와 메모리를 나눠 쓰지 않는 고정 RAM 장치에서는 예산에 닿기 전까지 유휴 메모리의 한계 비용이 0에 가깝다. 실효 T*는 메모리 압박 실험(설계 §3.2)으로 따로 정해야 한다.

### 4.8 연구 질문에 대한 현재 답 (시뮬)
- 고정 타임아웃 대비: T* = 0.3~1초에서 학습 예측(+대체)은 비용을 중앙값 7.5~13.1% 줄였고 진 트레이스가 없었다. T* = 1초의 이득은 주로 유휴 메모리 감소였다. T* = 3초에서는 줄고(−5.2%, 2패) 10초에서는 없었다.
- 단순 규칙 대비: 미리 정한 AI의 우위는 입증되지 않았다. 실제 고부하 트레이스의 T* = 1초에서는 AI가 앞섰고 T* = 3초에서는 규칙이 앞섰다. 탐색적 생존 모델은 두 조건 모두에서 규칙과 같거나 나았지만 확인이 필요하다.
- 실제 할당기와 메모리 제한 환경에서 유지되는가: 아직 재지 않았다.

## 5. 타당성 위협
- 유체 모델에는 단편화가 없다. 같은 빈 메모리에서 기존 할당기의 폴트가 이상적 타임아웃 모델의 1.9~2.3배였다(실측-VM, membench-guide §8.2). 학습 정책의 상대 이득이 청크 풀 실측에서 유지되는지 확인해야 한다.
- AI 생존은 시험 결과를 본 뒤 추가했다. 규칙과의 우열을 이 데이터로 주장하면 갈림길 선택(forking paths) 편향이 생긴다.
- 트레이스 10개, 시험 구간 약 15분이다. 부하가 낮은 BurstGPT 창은 시험 조각이 55·119개뿐이다. 부호 검정은 서술용이고 다중 비교를 보정하지 않았다. 시드 간 변동은 T* = 10초에서 트레이스당 최대 5.1%p(AI+대체)였다.
- BurstGPT 창은 시간 안에서 비정상적이다(3.7절). 결과가 창 고르기에 민감할 수 있다.
- 요청 크기는 토큰 수를 환산한 값이고 처리시간은 임시 모델이다. LLM 트레이스는 CrowdMap 부하가 아니다.
- 학습·검증의 관찰 절단에서 다시 쓰이지 않은 조각을 '나중에 다시 쓰인다'로 두었다. 0~300초 타임아웃 선택에는 영향이 없지만 분류기 정답(g > T*)에는 이 가정이 들어간다.
- 절대 이득이 MiB 단위다(4.1절). 상대 수치와 절대 수치를 함께 보고해야 한다.

## 6. 다음 단계
1. 방법 확정: 주 방법을 'AI 생존 + 온라인 문턱 보정 + 대체 장치'로 정하고, 규칙에도 같은 온라인 보정을 준다. κ 격자를 넓힌다. 개발은 지금 10개 트레이스에서 끝낸다.
2. 봉인 시험: 방법을 고정한 뒤 쓰지 않은 데이터(Azure LLM 추론 2024 1주 트레이스, BurstGPT의 다른 날·시간대 여러 개)에서 한 번만 잰다. Azure 2024 트레이스의 내려받기 여부와 크기는 확인이 필요하다.
3. C++ 청크 풀 실측(설계 §4): 재확보 CPU·RSS·폴트를 MADV_DONTNEED/MADV_FREE/munmap별로 재고, cgroup 메모리 상한을 바꿔 실효 T*를 정한다.

## 부록 A. 재현
```bash
# membench 폴더에서. 원본: AzureLLMInferenceTrace_{conv,code}.csv(Azure 2023), BurstGPT_1.csv
for p in periodic random poisson; do python3 traces.py synth --pattern $p --duration 3600 --out exp/traces/syn_$p.csv; done
python3 traces.py azure --in AzureLLMInferenceTrace_conv.csv --out exp/traces/az_conv.csv
python3 traces.py azure --in AzureLLMInferenceTrace_code.csv --out exp/traces/az_code.csv
while read q st n; do python3 traces.py burstgpt --in BurstGPT_1.csv --start $st --duration 3600 --out exp/traces/bg_q$q.csv; done < exp/bg_windows.txt
for f in exp/traces/*.csv; do python3 traces.py schedule --in $f --out exp/sched/$(basename $f) --workers 2; done
S=""; for t in syn_periodic syn_random syn_poisson az_conv az_code bg_q50 bg_q75 bg_q90 bg_q99 bg_q100; do S="$S exp/sched/$t.csv"; done
python3 paperexp.py $S --out exp/res                      # 2코어 약 15분
python3 paperexp.py $S --out exp/res_seed1 --no-loto --seed 1
python3 summarize.py exp/res > exp/summary.txt
```
- 위 명령으로 만든 트레이스·일정이 실험에 쓴 파일과 바이트 단위로 같음을 확인했다.
