## 5. 현재 범위와 2026-11-04 신규 후속 가설

### 5.1 기존 결과의 동결

- 기존 v1/v2 사전 등록, 봉인 결과, 작업 A·B 결과는 당시 기록으로 보존한다. 기존 결과 파일과 사전 등록 문서를 소급 수정하지 않는다.
- v2 봉인 41일 자료는 새 정책의 개발·튜닝 자료로 사용하지 않는다.
- G1은 이미 C3 선택·A·B에 사용한 개발 40일·420개 창의 탐색적 선별이다. 확증 자료가 아니다.

### 5.2 신규 후보: 저차원 생존 GBDT → 무손실 조회표

- 이전에 제안했던 15특징 교사 모델 → 학생 증류 → 수동 캐시/양자화 경로는 채택하지 않는다. 교사 추론 라벨링 비용과 근사 오차를 추가하기 때문이다.
- 새 후보는 실제 생존 라벨 `1[g > τk]`로 2특징 또는 3특징 생존 GBDT 10개를 직접 학습한다. 15특징 교사 출력을 학생 라벨로 만들지 않는다.
- 특징은 고정한 26개 개발 일정의 검증 구간에서 기존 `rule_groups`가 선택한 특징 빈도를 집계해 결정한다. 빈도 순위와 동률 규칙은 G1 전에 커밋한다.
- P1은 2특징, `max_bins=255`, 특징당 256개 상태(비결측 255 + 결측 1)의 256² 바이트 표(64 KiB)를 사용한다.
- P1b는 3특징, `max_bins=64`, 특징당 65개 상태(비결측 64 + 결측 1)의 65³ 바이트 표(274,625 byte, 약 268.2 KiB)를 사용한다.
- 각 표는 선택한 저차원 GBDT의 기본 반환 시간 인덱스(11개 선택지)를 저장한다. 이는 해당 저차원 모델 출력의 정확한 컴파일이며 15특징 모델과 동일한 예측이라는 뜻은 아니다.
- κ 보정·대체·C3 전환 규칙은 기존 그대로 둔다. 바꾸는 것은 생존 예측기뿐이다.

### 5.3 G1 개발 시뮬레이션 (11/05)

- 26개 고정 일정에서 특징을 선택하고 모델을 사전 학습한 뒤, 조회표와 모델 출력이 모든 420개 개발 창의 결정에서 인덱스 단위로 일치하는지 확인한다. NaN과 bin 경계도 시험한다.
- 예측기만 바꾼 C3를 420개 개발 창에서 평가하고, 재확보량 감소 `ΔR`과 유휴 보유량 감소 `ΔH`를 반드시 분리해 보고한다.
- 탐색 선별 기준은 합성 비용 모델 CPU 등가 `S_model·c ≥ 1.0 s`다(약 0.5 µs/결정, 0.43%p 상당). CPU-only 기준은 `ΔR·c`로 별도 평가한다. 합성 모델 비용을 CPU-only 이득이라고 부르지 않는다. CPU-only가 주 기준이고 `ΔR·c ≤ 0`이면, AI 추가 CPU가 양수인 한 G2로 진행하지 않는다.
- 후보가 모두 통과하면 `S_model·c`가 큰 후보 하나만 G2로 보낸다. 둘 다 실패하면 새 실험을 중단하고 현 원고를 제출한다.

### 5.4 G2 네이티브 CPU 계측 (11/06–07)

- 기존 c 측정과 같은 WSL·CPU 1 고정·단일 스레드에서 C++ 하네스로 규칙 전용 경로와 C3 경로를 3회 측정한다.
- 특징 계산, bin 변환, 표 조회, 9개 κ 후보 온라인 평가, 대체, C3 장부·전환까지 전체 추가 경로를 포함한다.
- κ와 C3 장부는 증분 합으로 계산하되, 구간 경계·동점 규칙을 보존하고 모든 결정·κ·전환 결과가 Python 기준과 일치해야 한다.
- `ΔI = CPU_C3 − CPU_rule`, `G_model = c(ΔR+ΔH/T*)−ΔI`, `G_CPU = cΔR−ΔI`를 함께 보고한다.
- 주 판정은 교수와 합의한 순이득 정의로 하며, 3회 측정 모두 양수여야 통과한다. 데이터 준비 `F_data`, 특징 선택 `F_select`, 학습 `F_fit`, 표 생성·검증 `F_table`을 모두 측정해 `F`와 `H* = F·Στ/G_op`를 계산한다. `G_op > 0`은 운영 중 순이득일 뿐 학습비를 회수한 생애주기 순이득을 뜻하지 않는다. 생애주기 순이득 주장은 사전에 정한 모델 재사용 기간 `H_deploy`가 `H*`보다 긴 경우에만 허용한다. `H_deploy`가 정해지지 않으면 `H*`만 보고한다.
- G2가 실패하면 후속 최적화를 더하지 않고 현재 원고를 제출한다.

### 5.5 Copilot 독립 확증 (11/08–09)

- G1·G2 모두 통과한 경우에만 prereg-v3와 코드·표 지문·판정 기준을 커밋한 뒤 원시 Copilot 자료를 연다.
- 26개 개발 일정에서 학습한 표를 재학습 없이 사용하고, v2와 동일한 변환 규칙을 적용해 한 번 평가한다.
- 데이터 확인 이후 정책·특징·판정 기준을 바꾸지 않는다. 일정 내 실행되지 않으면 G1/G2 결과는 탐색 결과로만 보고한다.

### 5.6 변경 사유

기존 §5의 “C++ 추론을 측정하지 않는다”, “조회표 경량 예측기를 만들지 않는다”는 제한은 2026-11-04에 수립한 신규 가설 G1/G2를 위해서만 예외적으로 개정한다. 기존 v1/v2 결과의 재실행·변경을 허용하는 것은 아니다. 새 가설은 G1·G2의 사전 고정 중단 기준을 따르며, G1/G2 실패 시 현 논문 원고로 복귀한다.
