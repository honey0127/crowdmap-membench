예측 기반 메모리 회수 정책이 메모리 관리에서 창출하는 가치로

## 4. 논문 목차와 각 절의 역할

### §1 Introduction (~800–1,200 words)

**역할**: 연구 동기, 핵심 질문, 접근 방식, 주요 발견, 기여 목록.

**핵심 흐름**:
1. 메모리 반납이 클라우드 컨테이너 환경에서 갖는 의미 (반납 후 재확보 비용)
2. 예측 기반 정책의 기회: 필요 없어질 메모리를 미리 반납
3. 경제성 질문의 필요성: 예측 모델 실행 비용이 절감 가치를 초과할 수 있다
4. 이 논문의 접근: 비용 모델 C = R + H/T*로 시뮬레이션 가치와 CPU 비용을 함께 측정
5. 주요 발견 요약 (부정 결과 포함)
6. 기여 목록: (a) 비용 모델, (b) 사전 등록 프로토콜, (c) G2W3 측정 형식, (d) 부정 결과, (e) 손익분기 분석

**주의**: 'AI가 메모리 관리를 개선한다'는 과장 금지. v2 PASS는 시뮬레이션 가치이고, G2 FAIL이 주 결론임을 명확히.

**주의**: "우리가 처음이다"라는 신규성 주장은 §7 조사 완료 전까지 금지.

### §3 Problem Formulation (~600–900 words)

**역할**: 비용 모델 정의, T* 의미, 판정 기준 G_model 도출.

**핵심 정의**:
- 비용 모델: `C = R + H/T*` (R = 반환한 메모리 MiB, H = 유휴 보유 MiB·s, T* = 환산 비율)
- T* 측정: 반납 25.6 µs/MiB + 재확보 256.2 µs/MiB = c = 281.8 µs/MiB; 실효 T* = 2.6 s
- G_model = c×(ΔR + ΔH/T*) − ΔI (G_model > 0이면 경제성 성립)
- G_CPU = c×ΔR − ΔI (ΔH/T* 항 제외 분해 지표; 주 판정에 쓰지 않음)
- 중요: G_model은 실제 CPU 절감 시간이나 클라우드 청구액과 같지 않음을 명시

**ΔR 해석**: ΔR = R_rule − R_C3; 현재 ΔR = −906 MiB는 C3가 규칙보다 906 MiB 더 많이 반환했다는 뜻. c×ΔR 항이 음수여서 G_model을 낮추는 방향으로 작용.

**핵심 절 구성**:

**4.2 평가 프레임워크 (두 차원)**:
- **차원 1**: 시뮬레이션 비용 (청크 풀 유체 모델, R과 H를 추적). v1·v2 봉인 판정.
- **차원 2**: CPU 경제성 (실제 추가 CPU ΔI vs G1_SMODEL_C). Task A, G2W3.

**4.3 P1b 조회표 (G1)**: 15특징 생존 모델 → 3특징 (높이, 사용량, 수준) 65³ 조회표 증류. 선택 기준: S_model×c 최대화. P1b = 1,560.860 ms > P1 = 1,483.856 ms.

**4.4 G2W3 측정 경계**:

### §7 Discussion (~1,500–2,200 words)

**역할**: v2 PASS / G2 FAIL의 관계 해석, ΔR의 의미, 경제성 미달 원인, 향후 방향.

**7.1 두 판정 차원의 관계**:
- v2 봉인 (H1v2~H3v2): 시뮬레이션 비용 모델에서 C3 메모리 절감 가치 확인
- G2: 그 절감 가치에서 실제 추가 CPU를 뺀 순이득 측정
- v2 PASS ≠ G2 PASS: 메모리 가치가 존재해도 CPU 비용이 더 클 수 있다

**7.2 ΔR의 의미와 비용 구조**:
- ΔR = −906 MiB: C3가 규칙보다 더 많은 메모리를 반환했다 (R_C3 > R_rule)
- c×ΔR = −255.3 ms: G_model을 낮추는 방향 (C3의 적극적 반환이 오히려 비용을 늘림)
- ΔH/T* = +6,444.9 MiB (등가): 규칙 대비 C3의 유휴 보유 절감 — G_model을 높이는 방향
- G_model이 양수가 되려면 ΔH/T* 항이 |c×ΔR| + ΔI를 모두 상쇄해야 하지만, 현재 ΔI가 너무 크다

**7.3 ΔI가 큰 원인 (추론 — 직접 근거 없음)**:
- G2W3 타이머 안에 포함된 추가 연산: compute_p1b_features, compute_Tk, online_kappa_T, run_fallback3 추가 2회
- 하위 연산별 분해 측정은 없음 → 논문에서 추론으로만 서술

**7.4 손익분기를 위한 방향 (추론)**:
- ΔI 경로 (−35%): compute_Tk, online_kappa_T 최적화; 단, run_fallback3 호출 축소는 정책 의미를 바꿈
- ΔR 경로 (부호 반전): 현재 C3는 규칙보다 더 많이 반환 (공격적). 손익분기에서는 더 적게 반환 (보수적) 필요 — 현재와 반대 방향
- T* 경로 (−31.8%): THP on + 2 MiB 환경의 T* ≈ 1.0 s에 근접; 단 사후 소급 조정은 불허
- 복합: 여러 변수 동시 개선 시 단일 목표보다 낮은 임계값

**7.5 B 분석과의 연결**:
- B: 조각별 정보 가치가 존재함 (2.49%p / 2.50%p)
- A/G2: 그 정보를 얻는 비용 (8배, 15배 초과)
- 따라서 "정보 없음" → "정보 있지만 얻기 너무 비쌈" 순서로 문제를 좁혔다
- 향후 방향: 조각별 정보를 더 싸게 얻는 설계 (새 후보, 새 사전 등록 필요)

### §8 Limitations (~600–900 words)

**필수 한계**:
1. **단일 환경**: WSL2(Intel Core Ultra 7 155H). 물리 서버, AWS Fargate 실제 환경 미확인
2. **유체 모델**: 실제 메모리 할당기 미검증. R과 H는 시뮬레이션 값
3. **단일 워크로드**: BurstGPT LLM 추론. Azure 14창은 v1에만 사용
4. **T* 환경 의존**: Fargate 가격 비율 가정. 다른 비용 구조에서는 다른 T*
5. **P1b ΔR은 유체 모델 값**: 청크 풀 재생에서 P1b C3 정책의 재확보량 직접 확인 없음
6. **G2W3 하위 연산 분해 없음**: ΔI의 출처를 compute_Tk, online_kappa_T 등으로 나누지 못함
7. **v1 모델 결함**: 조각 중점 특징 미래 정보 혼입. 사후 청크 모델 재계산에서 방향 유지됐지만 판정 대체 아님
8. **Task A는 Python 구현**: scikit-learn 단일 스레드. 최적화된 C++ 구현으로 일반화 없음
9. **Task B는 사후 분석**: 개발 데이터 사용, 봉인 데이터 미확인
10. **G2는 단일 하드웨어 × 3회**: 표준편차 92.873 ms (sample) / 75.831 ms (population); n=3의 한계

---

### §9 Conclusion (~300–500 words)

**역할**: 연구 질문에 대한 답변, 확인된 것과 확인되지 않은 것 명확히 분리, 향후 방향.

**핵심 문장 후보**:
- "P1b 기반 C3 정책의 추가 CPU 비용(평균 2,406 ms)은 모델 기반 메모리 절감 가치(1,561 ms)를 평균 845 ms 초과했다. 경제적 순이득은 성립하지 않았다."
- "C3의 시뮬레이션 가치는 실재했다(99.4~99.8%가 조각별 예측 정보에서). 경제성 미달은 정보의 부재가 아니라 정보를 얻는 비용의 초과 때문이었다."
- "손익분기 분석은 ΔI를 35% 줄이거나 ΔH를 47% 늘리는 조건이 필요함을 보였다. 이는 더 가벼운 조회표 증류 또는 더 보수적인 반환 정책 방향을 제시한다."

## 7. 논문 작성 전에 추가로 필요한 관련 연구 조사 항목

> 이 항목들은 §2 Background의 차별성 주장을 확정하고, 심사 위원의 "기존 연구와 어떻게 다른가?" 질문에 대비하기 위해 필요하다. 조사 전에는 "우리가 최초다" 류의 단언적 표현을 쓰지 않는다.

**A. 메모리 할당기의 감쇠(decay) 정책**:
- jemalloc `decay_ms`, TCMalloc `release_rate`, mimalloc `decommit_delay` — 고정 파라미터 기준선의 선례
- 이들 정책에서 T*(또는 그에 상당하는 환산 비율)를 명시적으로 측정한 연구가 있는가?

**B. ML 기반 메모리 관리**:
- 강화학습 기반 메모리 반납/할당 정책 (예: Clipper, Memtune, 클라우드 VM 메모리 관리 논문)
- 생존 분석을 메모리 reclamation에 적용한 선례 (있다면 직접 비교 필요)
- 조회표 기반 모델 증류를 메모리 정책에 적용한 선례

**C. CPU 비용을 함께 측정한 adaptive 메모리 정책 연구**:
- 정책 추론 비용(ΔI 상당)을 절감 가치와 함께 보고한 시스템 논문
- 없다면 비용 모델 C = R + H/T* 의 형태 또는 비슷한 메모리-CPU 환산 프레임워크가 있는지

**D. 캐시 교체 정책의 ML 적용 (유사 문제)**:
- LeCaR, Parrot, GL-Cache — 캐시 교체에서 ML 비용 vs 적중률 이득의 trade-off를 다룬 논문
- 이 분야에서 "정책 추론 비용이 절감 가치보다 크다"는 부정 결과를 보고한 연구

**E. 사전 등록과 봉인 평가 (시스템 연구에서의 방법론)**:
- 시스템 성능 평가에서 사전 등록이 쓰인 선례 (있는가?)
- 없다면 이 방법론 기여를 §4.6 또는 Supplemental에서 설명할 준비

**F. BurstGPT 데이터셋의 선행 연구**:
- BurstGPT 데이터셋을 메모리 관리 맥락에서 쓴 다른 논문이 있는가?
- 없다면 데이터셋 소개 문장에서 적절히 인용

## 8. 학술적 한계와 예상 심사 질문

### 예상 심사 질문 1: 단일 환경 한계

> "WSL2 단일 환경에서의 T* 측정이 어떻게 일반화될 수 있는가?"

**답변 준비**: T*는 Fargate 가격 비율을 포함한 평가 기준으로서 명시적으로 정의됐다. 다른 환경에서는 T*가 달라진다는 것 자체가 §8.4 한계에서 다루어진다. T* 경로 손익분기 분석이 이 질문에 대한 정량적 답변을 제공한다 (T* < 1.774 s이면 성립).

---

### 예상 심사 질문 2: G2 FAIL의 의미

> "FAIL이면 연구 결과가 단순히 부정적이지 않은가? 논문에서 무엇을 배울 수 있는가?"

**답변 준비**:
1. 비용 모델 프레임워크 자체가 기여 (G_model 공식, G2W3 측정 경계)
2. "정보 없음" → "정보 있지만 비쌈"으로 문제 위치 확정 (Task B + G2의 연결)
3. 손익분기 분석이 향후 설계 방향을 정량적으로 제시 (ΔI −35%, ΔH +47% 등)
4. 메모리 반납 정책에서 ML 비용 측정 방법론 자체가 기여

---

### 예상 심사 질문 3: v2 PASS와 G2 FAIL의 모순처럼 보이는 관계

> "시뮬레이션에서 통과했는데 CPU 측정에서 실패했다면, 평가가 일관성이 없지 않은가?"

**답변 준비**: §7.1에서 명시. 두 판정은 서로 다른 가설을 측정한다. v2는 "C3가 메모리 비용을 줄이는가?"를 측정; G2는 "그 절감 가치가 추가 CPU를 초과하는가?"를 측정. 같은 정책이 첫 번째 질문에서는 YES, 두 번째 질문에서는 NO가 될 수 있다. 이것이 비용 모델 프레임워크의 핵심 기여다.

---

### 예상 심사 질문 4: n=3 반복의 충분성

> "3회 반복만으로 G2 FAIL을 판정할 수 있는가?"

**답변 준비**: G_model 3회 최솟값은 −768.157 ms, G1_SMODEL_C = 1,560.860 ms, 즉 최소 ΔI조차 G1_SMODEL_C의 1.49배다. 3회 모두 같은 방향이고, 최대-최솟값 범위(180 ms)보다 평균 G_model 적자(845 ms)가 4.7배 크다. §7.4의 std(ddof=0) = 75.831 ms. 반복 수보다 효과 크기의 절대적 크기가 판정 근거임을 명시.

---

### 예상 심사 질문 5: Python 구현(Task A)과 C++ 구현(G2)의 비교

> "Task A(Python)와 G2(C++)가 다른 구현을 측정하는데, 함께 논의하는 것이 적절한가?"

**답변 준비**: Task A는 scikit-learn 15특징 모델의 순비용을 측정 (within C3, 사전 학습 C3). G2는 P1b 조회표 C++ 구현의 순비용을 측정. 두 판정 모두 순비용이 음수. 그러나 두 실험은 서로 다른 정책 구현이므로 수치 직접 비교는 하지 않는다 (§10.2). 각각 독립적으로 보고한다.

---

### 예상 심사 질문 6: T*를 소급 조정하면 통과 가능하지 않은가?

> "T*를 1.5초로 가정하면 G2가 통과하지 않는가?"

**답변 준비**: §8.2 (T* 경로). T* < 1.774 s 조건이고, WSL2 THP on + 2 MiB 환경의 실효 T* ≈ 1.0 s에 근접한다. 그러나 T*를 사후적으로 조정해 판정을 바꾸는 것은 판정 기준의 소급 변경이다. T*는 사전 등록 v2에서 2.6초로 고정됐다. T* 경로 분석은 미래 연구의 방향 제시이지, 현재 판정 변경이 아니다.
