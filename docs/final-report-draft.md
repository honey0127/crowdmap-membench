## 1장. v1 봉인 실험과 실패 원인

### 1.1 평가 조건

v1 봉인 실험은 사전 등록 v1.1(커밋 `0a3fc73`, 태그 `prereg-v1.1`)에 따라 2026-10-24에 실행됐다. 평가 모델은 청크 풀 유체 모델 시뮬레이션이고, 판정 T* = 1초였다. 평가 집합 R(실제 창 53개)과 S(합성 확인 창)를 사용했다. 비용 단위는 재확보 MiB와 유휴 보유 MiB를 T*로 나눈 합성 비용이다.

정책 세 개를 비교했다.

- **고정-온라인**: 그림자 장부로 반납 시점을 온라인 보정하는 단일 고정 타임아웃
- **규칙-온라인+대체**: 2특징(높이×수준)으로 나눈 칸마다 타임아웃을 장부로 조정하고 대체 장치를 갖춤
- **v1 주 AI(AI생존κ-온라인+대체)**: 15특징 HistGradientBoosting 생존 모델이 조각별 타임아웃을 계산하고 κ를 온라인 보정하며 대체 장치를 갖춤

### 1.2 판정 결과 (시뮬, [봉인 v1])

| 가설 | 비교 | 승/무/패 | p | d 중앙(%p) | 판정 |
|------|------|---------|---|-----------|------|
| H1 | v1 주 AI vs 고정-온라인 (R, 53창) | 37/12/4 | 1.0×10⁻⁷ | −7.68 | **충족** |
| H2 | v1 주 AI vs 규칙-온라인+대체 (R, 53창) | 9/14/30 | 0.0011 | +1.16 | **미충족** |
| H3 | 위 비교, S 칸별 (Holm 4) | — | Holm 0.36~1.00 | — | 네 칸 모두 미검출 |
| H4 | d의 요인 효과 (Holm 3) | — | — | — | 짧은 몰림만 확정 |

H2 미충족의 의미: 같은 온라인 보정·대체 장치 조건에서 2특징 규칙 정책의 시뮬레이션 비용이 AI 정책보다 낮았다(d 중앙 +1.16%p, 규칙에 불리한 방향이 양수). H1의 이득은 AI만의 이득이 아니었다. 같은 보정 조건을 쓰는 단순 규칙이 T* = 1초에서 더 많이 줄였다.

T*별 탐색 결과에서 두 정책의 순서는 T* = 1초(규칙 우세)에서 T* = 3·10초(AI 우세)로 뒤집혔다. 개발 데이터에서는 반대(1초에서 AI, 3초에서 규칙 우세)였다. 판정 T* = 1초는 개발 데이터에서 AI가 가장 유리해 보인 조건이었다(사전 등록에서 미리 밝힌 한계).

H4에서 짧은 몰림이 있으면 AI의 규칙 대비 이득이 작아졌다(p = 0.013, Holm). 크기 변동과 수준 변화 효과는 검출하지 못했다.

### 1.3 v1 모델의 결함

v2 준비 과정에서 v1 유체 모델의 결함 세 가지가 발견됐다(`causality-check.md` 참조).

1. **조각 중점 특징의 미래 정보 혼입**: 높이·수준·이전놀이 등 조각 중점 위치 특징에 결정 시각 이후의 도착 크기가 포함됐다. AI 쪽에 유리한 방향이었다.
2. **장부 반올림 잡음**: 대체 장치 장부의 '같음' 비교가 반올림 잡음으로 갈렸다.
3. **행 순서 의존**: 조각 배열의 행 순서가 미래 재사용 시각으로 정렬돼 생존 모델의 조기 종료 분할이 그 순서에 따라 달라졌다.

고친 청크 모델(`--model chunk`)로 같은 R 창을 사후 계산했을 때 H1·H2의 방향과 유의성은 유지됐다(H1: 36/14/3, p=3.6×10⁻⁸; H2: 9/9/35, p=1.1×10⁻⁴). 고정-온라인 대비 AI의 이득은 d 중앙 −7.68%p에서 −6.01%p로 줄었다. 미래 정보가 AI 쪽에 유리했던 몫과 같은 방향이다(추론). 사후 계산이며 판정을 대신하지 않는다.

## 2장. 모델 개선 및 C3 정책 개발

### 2.1 C3 정책의 구조

C3(AI→규칙대체)는 v1 주 AI와 규칙-온라인+대체 사이를 그림자 장부로 전환하는 정책이다.

- **전환 기준**: 최근 W = 300초 구간에서 비용이 더 낮은 경로를 선택한다(ε = 0, H = 0).
- **구성 요소**: v1 주 AI(+대체), 규칙-온라인+대체 — 두 경로 모두 완전히 실행되며 전환만 그림자 장부로 고른다.
- **C3의 이득 성격**: AI가 단독으로 규칙을 이기는 것이 아니라, 각 시간대에 더 나은 경로를 선택한 결과다(추론). v2 개발 결과에서 같은 BurstGPT 창의 T* = 3초에서 v1 주 AI 단독은 규칙과 비겼지만(19/4/17) C3는 이겼다(20/15/5).

### 2.2 후보 선택 과정 (사후 개발, [개발])

v1 봉인 창을 개발 데이터로 전환한 뒤, 사전에 정한 선택 규칙으로 C3를 골랐다(`v2-dev-results.md` §2).

선택 규칙: v1 R 창에서 T* = 0.3·1·3초 각각 'C3 vs 규칙' p < 0.05이고 승 > 패인 T* 수가 가장 많은 후보, 동점이면 d 중앙값 평균이 낮은 쪽, 고정-온라인 대비 후퇴 비율이 10% 초과하면 탈락.

청크 모델 기준으로 C1(후퇴 20.4%), C2(11.1%), C4(13.0%)가 탈락하고 C3(최대 9.3%)만 남았다.

### 2.3 P1b 후보 선정 (G1 탐색, [개발])

기존 15특징 생존 모델의 추론 비용을 낮추기 위해 저차원 생존 GBDT + 무손실 조회표 경로(G1 계획)를 도입했다. 계획 v4는 2026-11-04 커밋 이전에 고정됐다.

특징 선택 기준: 26개 개발 일정의 평균 상대 검증 비용이 가장 낮은 조합(커밋 `3912a9a`, 2026-11-04 11:42:48).

| 후보 | 특징 | 조회표 크기 | S_model × c (s) | G1 판정 |
|------|------|------------|----------------|---------|
| P1 | 사용량, 수준 | 256² = 65,536 bytes | 1.4839 s | 통과 |
| **P1b** | **높이, 사용량, 수준** | **65³ ≈ 268.2 KiB** | **1.5609 s** | **통과** |

둘 다 통과하면 S_model × c가 큰 후보를 G2로 보낸다는 사전 규칙에 따라 P1b를 선택했다.

G1 통과 기준: S_model × c ≥ 1.0 s(결정당 약 0.5 µs, 0.43%p 상당). G1은 개발 40일·420창의 탐색적 선별이다. 확증 결과가 아니다.

### 2.4 Python 및 C++ 실행 경로와 parity 검증

Python 기준선(`g2_prepare.py`)은 420창 각각에 대해 T_base, T_rule, T_rb, T_ai, T_ai_fb, T_c3, R, H를 계산하고 G2W3 형식으로 저장한다. C++ 하니스(`g2_harness`)는 같은 창을 처리하고 결과를 results/ 디렉터리에 저장한다.

parity 검증 결과: 420/420창, 7,671,239개 슬라이스 전수에서 T_base·T_rule·T_rb·T_ai·T_ai_fb·T_c3 배열 오차 = 0 (T_TOL = 0.0), R·H 오차 ≤ 1×10⁻⁹ (시뮬). checksum_rule = `b2bb4067b5354578`, checksum_c3 = `ba240bd4f8369334`는 공식 측정 3회에서 모두 동일했다.

## 3장. T* 측정

### 3.1 T*의 정의와 역할

비용 모델 `C = R + H/T*`에서 T*는 유휴 메모리 보유 비용과 재확보 CPU 비용 사이의 환산 비율이다. `c = 281.8 µs/MiB`를 `T* = 2.6 s`와 결합하면 `c / (1 MiB·s)⁻¹ ≈ 2.63 s`가 된다. T*는 연구자 WSL에서 측정한 반납·재확보 CPU 시간에 AWS Fargate 가격 비율을 곱한 평가 기준이다. 모든 운영 환경의 보편적 손익분기 시간으로 쓰지 않는다.

### 3.2 측정 절차 (실측, [3단계])

측정 조건: 1 MiB 청크, 4 KiB 페이지, MADV_DONTNEED, 묶음 16, 코어 1 고정, 반복 300회.

| 항목 | 값 |
|------|----|
| 반납 비용 | 25.6 µs/MiB |
| 재확보 비용 | 256.2 µs/MiB |
| c = 반납 + 재확보 | 281.8 µs/MiB |
| 실효 T* 3회 | 2.61, 2.64, 2.63초 |
| **판정 T*** | **2.6초** (중앙값 2.63초, 유효숫자 2자리) |

THP on + 2 MiB 청크 조건에서는 실효 T* ≈ 1.0초였다. 큰 페이지 환경에서는 v1 판정 T* = 1초 근처가 실제 환경에 해당한다. 이 경우 v1에서 규칙이 AI보다 나았던 영역이다(추론).

청크 풀 재생 160회에서 재확보량은 유체 모델 값과 모두 같았다. 실제 RSS와 장부상 상주량의 차이는 최대 0.2 MiB였다.

## 7장. G2W3 공식 CPU 측정과 경제성 평가

### 7.1 측정 경계 (G2W3 정의)

G2W3는 C++ 하니스 내부 타이머(CLOCK_PROCESS_CPUTIME_ID)가 측정하는 범위를 명확하게 정한 형식이다.

| 경로 | 타이머 안에 포함되는 연산 |
|------|--------------------------|
| **CPU_rule** | compute_grp_r (bin_ids + unique-remap), online_group_T (base + rule), run_fallback3, 비용 계산 |
| **CPU_C3** | CPU_rule의 모든 항 + compute_p1b_features (pos/D0/mD → x0,x1,x2), compute_Tk (인코딩+룩업+κ-스케일), online_kappa_T, run_fallback3 × 2 추가, 비용 계산 |

ΔI = CPU_C3 − CPU_rule은 C3 경로가 규칙 경로에 추가하는 순 CPU 시간이다. 파일 읽기·메모리 적재·출력 쓰기는 타이머 밖이다.

이 측정 경계는 G2W2 대비 개선됐다. G2W2에서는 compute_grp_r과 compute_p1b_features를 Python에서 사전 계산해 C++ 타이머 밖에 뒀다. G2W3에서는 두 연산을 C++ 타이머 안으로 이동했다.

### 7.5 경제성 계산

**G1 확정값** (`exp/v2dev/g1/simulation/summary.json`, G1 공식 실행 기준):

| 상수 | 값 | 출처 |
|------|----|------|
| ΔR = R_rule − R_C3 | −906.0 MiB | G1 시뮬레이션 (시뮬) |
| ΔH = H_rule − H_C3 | 16,756.7231 MiB·s | G1 시뮬레이션 (시뮬) |
| c | 281.8 µs/MiB | 3단계 측정 (실측) |
| T* | 2.6 s | 3단계 측정 → 동결 (실측) |
| G1_SMODEL_C = c × (ΔR + ΔH/T*) | 1,560.860 ms | 계산 |

**G_model** = G1_SMODEL_C − ΔI = c × (ΔR + ΔH/T*) − ΔI

이 지표는 비용 모델에서 C3 정책이 규칙 정책보다 절감하는 메모리 비용의 CPU 등가에서 C3 경로의 추가 CPU 시간을 뺀 값이다. G_model > 0은 C3의 메모리 절감 가치가 추가 CPU 비용을 초과한다는 뜻이다. 실제 CPU 절감량이나 실제 클라우드 청구액 감소와 같지 않다.

**G_CPU** = c × ΔR − ΔI

이 지표는 재확보량 감소에서 오는 CPU 절감에서 ΔI를 뺀 값이다. 유휴 메모리 보유량 절감(ΔH 항)을 포함하지 않는다. 메모리 제한이 없는 유체 모델에서 G_CPU만으로 판정하면 반납하지 않는 정책이 유리해질 수 있으므로, G_CPU는 비용 분해 지표로만 보고한다.

| 반복 | ΔI (ms) | G_model (ms) | G_CPU (ms) | G_model > 0? |
|------|--------|-------------|-----------|--------------|
| 1 (rule_c3) | 2,329.017 | **−768.157** | −2,584.328 | ✗ |
| 2 (c3_rule) | 2,379.671 | **−818.811** | −2,634.982 | ✗ |
| 3 (rule_c3) | 2,509.109 | **−948.249** | −2,764.420 | ✗ |
| 평균 | 2,405.932 | **−845.072** | −2,661.243 | ✗ |

G2 통과 기준: 3회 모두 G_model > 0. → **G2 최종 판정: FAIL**

규칙 정책 대비 C3 경로의 평균 CPU 증가율: (19,425.279 − 17,019.414) / 17,019.414 × 100 ≈ 14.14% (평균값 기준 계산).

### 7.6 G2 판정의 의미

이번 G2 FAIL은 현재 P1b 기반 C3 정책과 평가 워크로드에 한정된 결과다. 모든 AI 기반 메모리 관리 정책이 경제성이 없다는 뜻이 아니다.

구체적으로: C3 경로의 추가 CPU 비용(평균 ΔI ≈ 2,406 ms)이 C3가 창출하는 메모리 절감 가치(G1_SMODEL_C ≈ 1,561 ms)를 평균 845 ms 초과했다. 이 초과분은 주로 compute_p1b_features, compute_Tk(인코딩+룩업+κ-스케일), online_kappa_T, run_fallback3 추가 2회에서 발생한다.

Task A(Python 구현)와 G2(C++ 구현)의 관계: Task A는 Python scikit-learn 구현으로 within C3와 사전 학습 C3의 순비용을 판정했고, G2는 C++ 하니스로 P1b 조회표 기반 C3의 순비용을 판정했다. 두 판정 모두 순비용이 음수였다. 그러나 두 실험은 서로 다른 정책 구현을 측정한 것이므로 직접 수치 비교는 주의가 필요하다.

## 8장. 손익분기 민감도 분석

민감도 분석은 현재 G2 판정을 사후적으로 뒤집는 수단이 아니다. 현재 P1b 기반 C3 정책의 경제성이 성립하기 위해 각 변수가 어떤 조건을 충족해야 하는지를 보여 주는 참고 계산이다.

기준: 평균 ΔI = 2,405.932 ms, G1_SMODEL_C = 1,560.860 ms.

### 8.1 손익분기점 요약

G_model = c × (ΔR + ΔH/T*) − ΔI > 0 조건을 각 변수에 대해 풀면:

| 변수 | 현재값 | G_model > 0 조건 | 필요 변화량 | 비율 |
|------|--------|----------------|-----------|------|
| **ΔI** | 2,405.932 ms | < 1,560.860 ms | −845.072 ms | −35.1% |
| **T*** | 2.6 s | < 1.7744 s | −0.826 s | −31.8% |
| **c** | 281.8 µs/MiB | > 434.371 µs/MiB | +152.6 µs/MiB | +54.1% |
| **ΔH** | 16,756.72 MiB·s | > 24,553.699 MiB·s | +7,796.97 MiB·s | +46.5% |
| **ΔR** | −906.0 MiB | > +2,092.837 MiB | +2,998.837 MiB | 부호 반전 |

경계값(1,560.860 ms 등)은 G_model = 0이 되는 점이다. G_model > 0 조건을 충족하려면 경계값을 초과(엄격 부등호)해야 한다.

**ΔR에 대한 주의**: 현재 ΔR = R_rule − R_C3 = −906 MiB는 C3가 규칙보다 906 MiB 더 많은 메모리를 반환했다는 뜻이다 (R_C3 > R_rule). 손익분기를 위해서는 ΔR이 −906 MiB에서 +2,092.837 MiB 초과로 변해야 하므로 약 +2,998.837 MiB의 변화가 필요하다. 이는 C3가 규칙보다 메모리를 더 적게 반환하는 방향이며 (R_rule > R_C3), 현재 정책 행동과는 반대 방향이다.

### 8.2 각 변수의 의미

**ΔI 경로**: C3 경로의 추가 CPU를 현재의 약 35% 줄여야 한다. compute_Tk(인코딩+룩업+κ-스케일)와 online_kappa_T의 최적화, 혹은 run_fallback3 추가 호출 횟수 축소가 후보 방향이다. 단, run_fallback3 호출 횟수를 줄이면 C3 정책의 의미가 달라지므로 별도 정책 후보로 취급해야 한다.

**T* 경로**: T*를 2.6s에서 1.7744s 미만으로 낮춰야 한다. 이는 THP on + 2 MiB 청크 환경의 실효 T*(≈ 1.0초)에 근접한 값이다. 단, T*를 사후적으로 조정해 G_model을 양수로 만드는 접근은 기존 판정 기준의 소급 변경이므로 허용되지 않는다.

**c 경로**: c가 현재 281.8 µs/MiB에서 434.371 µs/MiB 초과여야 한다. c는 측정값이므로 임의로 올릴 수 없다. 다른 하드웨어 환경에서 재확보 비용이 더 높을 경우에만 해당한다.

**ΔH 경로**: C3가 규칙보다 유휴 메모리 보유량을 현재보다 46.5% 더 줄여야 한다. 정책 최적화 없이는 달성하기 어렵다.

### 8.3 복합 조건

단일 변수 조건이 아니라 여러 변수를 동시에 개선하면 손익분기 조건이 완화된다. 예를 들어 ΔI를 20%, T*를 15% 개선하면 G_model > 0이 될 수 있다. 이 가능성을 현재 실험으로 확인하지 않았으므로 가능하다거나 불가능하다고 단정하지 않는다.

## 10장. 근거 부족 주장 목록

다음 항목은 현재 보고서에서 주장하거나 논문에서 언급할 수 있지만, 직접적인 근거가 없거나 추가 설명이 필요한 사항이다.

1. **G2W3 측정 경계가 G2W2 대비 개선됐다는 주장의 계량화**: G2W2 측정값이 없으므로 경계 차이의 크기를 수치로 비교할 수 없다. "G2W3는 compute_grp_r과 compute_p1b_features를 타이머 안으로 이동했다"는 구조적 설명만 가능하다.

2. **Task A와 G2의 직접 비교**: Task A는 Python scikit-learn 구현, G2는 C++ 조회표 구현이다. 두 ΔI를 직접 비교하면 오해가 생길 수 있다. 비교 가능한 단위로의 환산 근거가 없다.

3. **G2 FAIL의 원인 분해**: 평균 ΔI 2,406 ms 중 compute_p1b_features, compute_Tk, online_kappa_T, run_fallback3 각각의 기여 비율. `g2_harness.cpp`의 타이머 구조에서 하위 측정값이 없으므로 추론으로만 서술할 수 있다.

4. **P1b 조회표와 기존 15특징 모델의 추론 비용 비교**: G1은 P1b 조회표의 시뮬레이션 이득(ΔR, ΔH)을 측정했지만 추론 비용(ΔI)은 G2에서 처음 측정했다. 기존 15특징 모델의 ΔI는 측정하지 않았다.

5. **청크 풀 재생에서 P1b C3 정책의 재확보량 일치 여부**: 3단계 재생은 v1 주 AI와 규칙으로 160회를 확인했다. P1b 기반 C3 정책은 같은 재생을 거치지 않았다. ΔR은 유체 모델 시뮬레이션 값이다.

6. **Copilot 독립 확증 (5.5절)**: G1·G2 모두 통과한 경우에만 진행하기로 계획했다. G2 FAIL로 실행하지 않았다. 논문에서는 "Copilot 독립 확증을 계획했으나 G2 FAIL로 실행하지 않았다"고 기재한다.

7. **H* (사전 학습비 회수 기간)**: G_op ≤ 0이므로 유한한 H*가 없다. Task A의 사전 학습 C3와 G2의 P1b 기반 C3는 다른 구현이므로 각각 별도로 적시해야 한다.

## 부록 B. 용어 정리

| 용어 | 정의 |
|------|------|
| ΔI | CPU_C3 − CPU_rule (G2W3 타이머 기준 순 추가 CPU 시간) |
| G_model | c × (ΔR + ΔH/T*) − ΔI (합성 비용 모델 순이득, 주 판정 지표) |
| G_CPU | c × ΔR − ΔI (CPU-only 순이득, 비용 분해 지표) |
| G1_SMODEL_C | c × (ΔR + ΔH/T*) = G1 시뮬레이션에서 계산한 메모리 절감 가치의 CPU 등가 |
| c | 반납 + 재확보 단위 비용 (281.8 µs/MiB, 3단계 실측) |
| T* | 비용 모델의 메모리-CPU 환산 비율 (2.6 s, 3단계 실측 → 동결) |
| ΔR | R_rule − R_C3 (규칙 대비 C3의 반환량 차이; 음수면 C3의 반환량이 규칙보다 많다, 즉 C3가 더 적극적으로 메모리를 반환했다) |
| ΔH | H_rule − H_C3 (규칙 대비 C3의 유휴 보유량 감소분) |

| (실측) | 실제 타이머로 측정한 값 |
| (계산) | 측정·시뮬레이션 값에서 수식으로 계산한 값 |
| (추론) | 관측에 기반한 해석, 직접 증거 없음 |
